# Tin Hat actions contract (ACTIONS.md) — format v1

Status: **normative** for Tin Hat 11.0 step 3 (buttons). Owner: the buttons track. Byte-identical in both repos:
web `src/actions/ACTIONS.md`, desktop `crates/actions/ACTIONS.md`; the source is the shared contract directory.

DESIGN (the modular-UI design notes → Buttons, 2026-09-26): *every action in the app gets one entry in a
shared action list (id, label, icon, and when it applies), and every button row is simply a list of those ids, so
any button can go in any row.* This file says what an action is, how both apps decide whether it applies and how it
looks right now, how button rows are stored and drawn, and how the Ctrl+K palette finds things. Behaviour (what an
action does) stays in each app (§14); availability, presentation, rows and ranking are shared code proven by the
vectors (§12).

## 2. The table

```jsonc
{
  "format": "tinhat-actions", "version": 1, "doc": "…",
  "groups":      [{"id": "calls", "label": "Calls"}, …],   // calls · fun · rooms · you · app · navigation (palette/drawer order)
  "predicates":  {"<name>": Predicate},                    // the availability vocabulary (§4.2)
  "states":      {"<name>": State},                        // toggle sources and {text} placeholders (§6)
  "valueTypes":  {"<type>": ValueType},                    // stored target values (§5.4)
  "paramTypes":  {"<type>": {"doc"}},                      // target params (§5.5)
  "targetKinds": {"<kind>": TargetKind},                   // §5.1
  "contexts":    {"<id>": {"provides": [kind…], "doc"}},   // where context-only actions live (§3.2)
  "scopes":      {"<scope>": {"parent"?, "doc"}},          // shortcut scopes (§8)
  "keys", "webKeys",                                       // key names and the web's contested keys (§8)
  "limits":      {"rowItems": 24, "rowsPerIsland": 8, "targetKeys": 4, "idChars": 64, …},
  "placeholder": {"label", "icon", "tip"},                 // a newer Tin Hat's button (§9.5)
  "palette":     {…},                                      // the Ctrl+K palette's numbers and texts (§10)
  "rows":        {"<island>.<row>": RowKind},              // §9.1
  "menus":       {"<menu>": Menu},                         // §9.7
  "actions":     [Action, …]                               // sorted by id
}
```

Nothing iterates the table in JSON key order: registries are looked up by key; every ordered walk is explicit
(the `actions` array order, `groups` order, code-point order of keys, a list's own order).

## 3. Actions

### 3.1 Fields

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | string | `^[a-z][a-zA-Z0-9]*(\.[a-z][a-zA-Z0-9]*)+$`, ≤ 64 characters, object-first (`call.mic.toggle`, `room.leave`, `sound.play`). Unique, never reused. A stored id is any string of the layout's item syntax `[a-z][a-zA-Z0-9.]{0,63}` (LAYOUT.md §3.9); an id this version does not know is a newer Tin Hat's (§9.5). |
| `group` | string | A `groups` id — the palette and drawer section. Metadata, not part of the id. |
| `label` | string | The canonical label (menus, palette, tooltips when there is no `tip`). |
| `shortLabel` | string? | For icon-and-label buttons and phones ("Rec" for "Record calls here (Memories)…"). |
| `tip` | string? | Hover text when it differs from the label (today's tooltips). |
| `keywords` | string[]? | Extra palette search words ("microphone", "BRB"). |
| `icon` | string \| null | An icon name present in **both** icon packs (web `public/iconpack`, desktop iconpack ∪ Breeze; the validator checks). `null` only when the button draws its target (a room's avatar, a sound's emoji, a status preset). |
| `iconByApp` | {desktop?, web?}? | Escape hatch when a glyph must differ; `notes` says why. |
| `apps` | ("desktop" \| "web")[] | Where the action exists. A one-app action says why in `notes` (a WEB-EXCEPTION or a pending parity item). |
| `requires` | When? | Capability / permission: false ⇒ the action is **hidden** everywhere (§4). |
| `when` | When? | Applicability: false ⇒ **unavailable**: a button dims (or hides with `hideWhenOff`), a menu row greys. Absent = true. |
| `target` | Target? | §5. |
| `toggle` | Toggle? | §6. |
| `variants` | [{when, label?, shortLabel?, icon?, tip?}]? | The first whose `when` holds changes the face (§7.2): "Start a call" / "Join the active call". |
| `split` | {a, target?}? | The small ▴ part of a call-bar button: the action (and target) it runs ("Mute ▴" → `call.options.open` value `mic`). |
| `targetFace` | Face? | The face of a button whose target is stored in its row item: `{label?, shortLabel?, icon?, tip?, emoji?}` with `{name}` (§7.2): a "Join Gaming Central" / "Bruh" / "Goose" button. |
| `primary` | true? | The surface's one call to action (the composer's Send): drawn as the CTA. |
| `confirm` | Confirm? | §7.4. Asked from every surface (button, menu, palette, key); it cannot be switched off. |
| `danger` | true? | Red styling (`call.leave`, `room.leave`). |
| `hold` | true? | Press-and-hold (push to talk): a button keeps it pressed while held; never in the palette. |
| `contexts` | string[]? | Non-empty = **context-only**: it acts on the thing its surface provides (a message, a tile, the composer); placeable only in a row or menu that provides one of these contexts, never in your own button islands or the palette. |
| `shortcut` | Binding[]? | Default key bindings (§8). |
| `palette` | false? | Never listed in the palette (§10.2): the palette's own rows and people do the job (`nav.room.open`, `person.message`), or it is the palette itself (`nav.quickSwitcher.open`), or a menu (`app.menu.open`). |
| `pending` | string? | Declared but not wired yet (none since 11.0: `layout.edit` was wired with edit mode, EDITMODE-UI.md). Never in the palette. |
| `since` | "11.0" | |
| `notes` | string? | Not shown. |

### 3.2 Contexts and placeable actions

An action without `contexts` is **placeable**: it can go into any button row (incl. your own `buttons` islands) and
the palette lists it (§10.2). A context-only action gets its subject from the surface — the context object
`{<subject kind>: id, …}` a row or menu supplies (a message row supplies `{message, room}`). The table's `contexts`
registry says what each context provides; a row kind (§9.1) or menu (§9.7) names the contexts it provides.

## 4. Availability

### 4.1 Rules

```jsonc
When := "<predicate or state name>"         // true iff the value is the JSON boolean true
      | {"not": When} | {"all": [When…]} | {"any": [When…]}   // all [] = true, any [] = false
      | {"eq": ["<enum name>", "<value>"]}  // the value is that string
      | {"param": ["<param or kind key>", "<value>"]}          // the resolved target / invocation holds that value
```
An object with more or fewer than one key, an unknown operator or a malformed operand is **false**. Every name must be
declared (validator). Evaluation reads a **snapshot** (§4.3) and never has side effects.

### 4.2 Predicates and states

`predicates` / `states` entries: `{type: bool | enum | text | list, scope, doc, values?, source?}`. `scope` is
`global` or a subject kind (`room`, `space`, `person`, `message`, `tile`, `sound`, `event`, …). A scoped name reads
the value of the subject the evaluation is about (§5.7): the action's resolved target subject, or a subject the
context supplies. No such subject, or no value ⇒ the value is absent (a rule on it is false). `source: "app"` marks
a value derived from the evaluating app, never read from the snapshot: `platform.web` is true exactly in Tin Hat Web.

### 4.3 The snapshot

```jsonc
{
  "values":   {"call.in": true, "prefs.callLayout": "auto", …},            // global names
  "subjects": {"room": {"!id": {"name": "Gaming Central", "alias"?: "#…", "values": {"room.joined": true, …}}},
               "person": {"@id": {"name", "values"}}, "space": {…}, "theme": {…}, "sound": {…}, "device": {…}, …},
  "current":  {"room"?: "!id", "activeSpace"?: "!id"},                    // the absent-rule defaults (§5.3)
  "local":    {"<local id>": {"<kind key>": "<device-local value>", "label"?: "…"}},   // §5.2
  "lists":    {"room": [ids in the nav's order], "invite": [pending invites, newest first], "person": […], "theme": […],
               "inputs"|"outputs"|"cameras"|"audioSources": […]}
}
```
Each app builds it from its real state (§14.2). Anything missing reads as absent; anything of the wrong JSON type reads
as absent (a string `"true"` is not true). A subject the snapshot does not list does not exist (§5.7). A pending
invite to a room or a DM is a `room` subject with `room.invited` true (and `room.joined` not); `lists.invite` holds
them newest first — the invite's time (your own `m.room.member` event; unknown = the oldest), then the lower-cased
name (code-point order), then the id (the DM strip's rule). A space you are invited to is a `space` subject
(`space.invited`), never a `room` one.

## 5. Targets

### 5.1 Target kinds

`targetKinds.<kind>`: `{key?, value?, subject?, stored, portable, picker?, fallbackName, doc}`.
- **Stored** kinds are written into a row item's `target` under `key` (`room`, `space`, `rail`, `person`, `sound`,
  `status`, `theme`, `pane`, `device`, `source`, `value`). Their values have a value type (§5.4).
- **Context** kinds (`message`, `tile`, `participant`, `event`, `invite`, `inviteCode`, `session`, `video`) are never
  stored: the subject comes from the context — or from a host picker (`absent: "pick"`, e.g. the hidden-streams menu).
- `subject`: the snapshot subject kind the value names (a `room` target names a room subject). A listed value of a
  type with `values` (`railSpace`'s home / favourites / people / orphans) names no subject; its `or` alternative (a
  space's room id) does.
- `portable: false` (`device`, `audioSource`) = **device-local** (§5.2).

### 5.2 Device-local targets

A device-local target is stored as `{"local": "<1–12 of a–z0–9>"}`; the device's own table (not synced; snapshot
`local`) maps it to `{<kind key>: value, label?}`. On another device (or after the device is gone) the local id does
not resolve: the button then **picks** (§5.7) instead of failing. A raw device value in a stored target is refused
(`not-portable`); a **transient** target (run, never stored: a palette choice) may carry it.

### 5.3 The target spec of an action

`target: {kind, absent?, picker?, values?, labels?, shortLabels?, icons?, params?, pickable?}`:
- `absent` — what a button without a stored target acts on: `currentRoom` / `activeSpace` (snapshot `current`),
  `pick` (running it opens its picker: palette stage 2, §10.6, or the host's own picker), `none` (no subject; the
  action has a meaning without one: `calendar.open` opens the current space's calendar). Absent `absent` on a stored
  kind = the target is required (missing ⇒ unavailable, §5.7).
- `values` — the `choice` kind's own values (`call.layout.set`: auto / gallery / speaker / sidebar).
- `labels` / `shortLabels` / `icons` — per stored value (status presets, rail entries, settings panes, choices).
- `params` — extra named values beside the subject (`status.set`: `text`, `emoji`, `colour`; `space.settings.open`:
  `tab`); `{type: enum|text|emoji|colour|int, values?, labels?, shortLabels?, icons?, required?, max?, min?}`.
- `pickable: false` — never stored in a row (it always acts on the absent rule / context).

### 5.4 Value types

`valueTypes.<type>`: checked in this order: a listed `values` string is valid; else `or` (the value must be valid for
that type); else `prefix` (one of), `min`/`max` (length in **code points**), `token` (no space, no control, no line
separator, no lone surrogate), `server` (a `:` after a non-empty localpart and a non-empty server), `charset`. Text
types refuse control characters (U+0000–U+001F, U+007F–U+009F) and U+2028/U+2029. `enum` = the action's
`target.values`. Only strings are values.

### 5.5 Params

`enum`: one of `values`. `text`: 1..`max` (default 80) code points, no controls. `emoji`: 1–16 code points, token
rules. `colour`: `#rrggbb`, hex digits in either case, **normalized to lower case**. `int`: an integer JSON number in
[min, max]; `-0` becomes `0`.

### 5.6 Validating a stored target (`validateTarget(action, target, transient = false)`)

No target (`undefined`) is valid. Else the first failure in this order: `not-object`; `too-many-keys` (more than
`limits.targetKeys`); an empty object is valid; `not-targetable` (the action has no target spec); then each key in
code-point order: the kind's `key` → `not-pickable` (pickable false), `not-portable` (a device-local kind and not
transient), `bad-value`; `local` (device-local kinds only) → `not-pickable`, `bad-local`; a declared param →
`bad-value`; anything else → `unknown-key`. The result holds the normalized values (§5.5). Placing an item (§9.3)
and resolving one (§5.7) use this.

### 5.7 Resolving (`resolveTarget`)

1. The context's string entries become subjects (`{kind: id}`), in code-point order of the kinds.
2. The stored target is validated (§5.6); a failure ⇒ **target-invalid** (the reason kept), stop.
3. Invocation params (a key binding's or a host's) are validated against the declared params; a bad or undeclared
   one ⇒ target-invalid `bad-param`, stop.
4. Params: the stored ones, then the invocation's (the invocation wins).
5. The value: the target's `key` value; else a `local` id resolved through snapshot `local` (a missing entry or an
   invalid value there ⇒ **pick**; a label there names the target).
6. A value that is a listed literal of its type (or of a kind without a subject) becomes a param under the kind's key;
   else it names the subject of the kind (`subjects[kind.subject] = value`).
7. No value and no subject of the kind from the context: `currentRoom` / `activeSpace` take `snapshot.current`
   (missing ⇒ **target-missing**); `pick` ⇒ **pick**; no `absent` ⇒ target-missing; `none` ⇒ nothing.
8. A required param still missing ⇒ **pick**.
9. A subject that came from the stored target or the absent rule must exist in the snapshot's `subjects`; else
   **target-unknown** (a left room, a deleted sound, a removed theme dims the button — never an error).

## 6. Toggles

`toggle: {state, on?, off?, activeWhen?}` — the button is **active** (pressed, accented) when the state's value
equals: `true` (no `activeWhen`), a literal `activeWhen` string, the resolved param (`{"param": "<name>"}`: the
layout button "Gallery" is active while the layout is gallery), or the resolved subject id (`{"subject": true}`: the
theme button "Goose" is active while Goose is the theme). A `list` state is active when it holds the wanted value.
`on` / `off` faces change label / icon / tip (§7.2). A state named like a predicate is that predicate.

## 7. Presentation (`present`)

### 7.1 Stages

The first failing stage names `why`: `unknown` (no such action) → `app` (not in this app) → `context` (a context-only
action where no provided context fits) → `form` (a menu item for the other form) → `target` (§5.7 error:
`whyTarget` = `target-invalid:<reason>` | `target-missing` | `target-unknown`) → `requires` (the action's, and the
row kind override's, §9.1) → `when` (the action's, the row override's, the menu item's). `visible` is false for
unknown / app / context / form / requires; `enabled` is false for every failure. `pick` (§5.7) does not fail: the
button is enabled and running it picks.

### 7.2 Faces

The label, shortLabel, icon, tip and emoji start from the action (emoji: none) and are overlaid in this order: the
target value's faces (the stored key's value: `labels` / `shortLabels` / `icons` / `emojis`; then each enum param in
code-point order: its `labels` / `shortLabels` / `icons`), the toggle's `on` or `off` face, the **first** variant whose `when` holds, the action's
`targetFace` — only when the target's value came from the STORED item (its key or a device-local id), never from the
absent rule or a context: "Join {name}", "{name}" (a sound, a theme, a person) —, the row kind's override (§9.1), a menu
item's `label`. `iconByApp` replaces the icon for its app first. `emoji` (a status preset's 🎯) is drawn as the glyph
when present (hosts prefer it to the icon).

### 7.3 Text placeholders

In labels, tips and confirm texts, `{name}` is the target's name: the subject's `name`, a device-local `label`, the
listed value's label (or the value), else the kind's `fallbackName` ("this room"). `{<text state>}` is that state's
string — a global one (`{update.version}`, `{call.soundName}`) or one of the evaluation's subject (`{room.pinnedCount}`,
`{room.activity}`); an absent value fills nothing. Anything else in braces stays literally.

### 7.4 Confirm

`confirm: {kind: destructive|consent, title, text, confirmLabel, askReason?, onlyWhen?, variants?}` — asked only while
`onlyWhen` holds (status.set asks only when it turns sharing on); the first matching variant replaces texts; texts get
§7.3 placeholders. Presentation carries the resolved `{kind, title, text, confirmLabel, askReason}` or null.

### 7.5 Output

`{exists, visible, enabled, why, whyTarget, pick, active, label, shortLabel, icon, tip, look, danger, primary, hold,
subject, params, targetName, targetIcon, emoji, confirm, split}` — `look` = the row override's look or null; `split` =
`{a, target}` of the ▴ part or null; `emoji` = the face's emoji or null.

## 8. Shortcuts

### 8.1 Sequences

`shortcut: [{keys: [sequence…], scope, typing?, fixed?, web?, desktop?, rank?, params?}]` — an action's default
bindings. A sequence is Qt text: modifiers `Ctrl+Alt+Shift+Meta` in that order, then one key (`keys.named`, `F1`–`F24`,
a letter or digit, `keys.punctuation`): `Ctrl+Shift+M`, `Alt+Shift+Up`, `F11`; or one modifier alone (a **bare**
modifier — push to talk's `Ctrl`). `parseSequence(text)` (web `keys.ts`, desktop `keys.rs`) reads any spelling —
modifiers in any order, ASCII case-insensitive, `keys.aliases` (`esc`, `enter`, `cmd`, `pgdn`, `plus` …), spaces around
the text and its tokens, a trailing `+` key (`Ctrl++`, the two `+` side by side) — and answers the canonical text, or the first failure: `not-string`, `empty`,
`too-long` (more than `limits.sequenceChars` code points), then per token left to right `empty-token`, `key-not-last`,
`duplicate-modifier`, `two-keys`, `unknown-key`, finally `no-key` (modifiers only, more than one). `web` / `desktop`
replace `keys` for that app. `scope`: `app` ⊃ `main` ⊃ `composer` / `conversation`; `window:<id>` for tool windows (§2
`scopes`). `typing`: also while a text field has focus. `fixed`: not re-bindable (Return sends). `webKeys.reserved`
are the browser's own (Ctrl+T/W/N…), `webKeys.browser` the ones a page may take while it has focus (`webClass`).

### 8.2 Default bindings

`defaultBindings(app)`: for every action of the app in table order, every spec, every key of the app → `{action, key
(canonical), scope, typing, fixed, rank (default 0), hold, source: "default", params (code-point order)}`. The
validator checks the syntax, the canonical spelling and that no two defaults of one app clash in overlapping scopes;
`rank` (an integer ≥ 1) only orders fixed defaults. An assignable action (§8.3) has its first default in scope `app`
or `main` and no `params` on its defaults: the hosts run a person's key main-window- or app-wide and without params.

### 8.3 Who may get a key

An action is **assignable** in an app when it is in the app, placeable (no `contexts`), not `pending`, none of its
defaults is `fixed`, and it needs no stored target (no `target`, or one with an `absent` rule: a key runs it on the
room on screen, or opens its picker — palette stage 2). "Any action can get a keyboard shortcut" (DESIGN) = every
assignable one.

### 8.4 Checking a person's key (`checkUserBinding(app, action, text)`)

The first failure: `unknown-action`, `other-app`, `not-assignable`, `bad-sequence`, `reserved` (`keys.reserved`:
Escape, Tab, Shift+Tab, F6, Shift+F6), `hold-key` (a `hold` action — push to talk — takes a modifier held alone or an
F-key without modifiers), `hold-only` (a modifier alone is only for a hold action), `needs-modifier` (outside a window
scope a key needs Ctrl, Alt or Meta, or is an F-key: a plain or Shift+ letter types), `browser-reserved` (web only:
the browser never hands it to a page), `fixed-taken` (a fixed default of the app holds it in an overlapping scope).
Passing answers `{key (canonical), scope, typing}` — the scope and typing of the action's first default spec, else
`app` and typing on.

### 8.5 The user document (device-local)

`{"format": "tinhat-shortcuts", "version": 1, "bindings": {"<action id>": [sequence…]}}` in the device pref
`shortcuts` (never synced: keyboards differ per device). An entry replaces the action's defaults (`[]` = no key); an
action without one keeps its defaults. `readUserBindings(app, doc)` never fails; anything unusable is a note:
`not-object`, `too-large` (canonical JSON over `limits.bindingsBytes` UTF-8 bytes), `bad-format`, `bad-version`,
`bad-field bindings`, `too-many-actions` (over `limits.bindingsActions`, the first ones in code-point order kept),
`other-app <id>` / `unknown-action <id>` (the entry is kept verbatim — another app's or a newer Tin Hat's — so a save
never drops it), `bad-entry <id>` (not a list), `too-many <id>` (over `limits.bindingsPerAction`, the first kept),
`bad-sequence <id> <index>`, `duplicate <id> <key>`, `<check error> <id> <key>` (§8.4), `no-usable-key <id>` (a
non-empty list whose every key failed: the entry is dropped and the defaults stay — only `[]` means "no key"). A newer
version's document is not read (`bad-version`); the first edit on this device replaces it (the document is
device-local, so only a downgrade meets one).

### 8.6 The bindings in effect, clashes

`effectiveBindings(app, doc)`: the defaults — an action with an entry drops its non-fixed defaults — then the
entries' keys by action id (`source: "user"`, rank 0). Two bindings of different actions with the same key in
overlapping scopes **clash** (not both fixed): `conflicts` lists every pair in list order `{key, actions: [a, b],
scopes: [a, b]}`. The **dispatch order** of bindings that share a key: rank, a person's own before a default, action
id (code-point), list order; `wins` = no binding of another action with the same key in an overlapping scope comes
before it. So a key a person gave to another action takes the key from its default owner (flagged as a clash): a
person's binding has rank 0 and ranks are ≥ 1, so no default comes before it. `wins` is computed over overlapping
scopes, not per press: the loser never runs, even where the winner is unavailable or doesn't take typing.

### 8.7 Matching a key press

`matchKey(bindings, key, scope, typing)` → the actions a press runs, in order: bindings of that canonical key whose
scope is in the chain of the focused scope (innermost first, then the dispatch order), typing ones only while a text
field has focus, a non-fixed binding only when it `wins` its key (§8.6 — fixed ones share keys across nested scopes and
focus decides between them); `hold` bindings left out (their host watches the key's press and release: push to talk engages
while the key is held, ends on release or when the window loses the focus). A host runs the first one that is
available right now (§14.1) and consumes the key only then. Hosts: web — the page's one keydown listener
(`core/shortcuts.ts`) asks the actions feature first: a person's key runs through the run path; a default registered
by a feature runs only while it still `wins` its key; desktop — each default's `Shortcut` takes the action's winning
keys, a person's keys to other actions get a `Shortcut` of their own (ActionsHost.qml; scope `app` = an
ApplicationShortcut, `main` = a WindowShortcut of the main window), push to talk reads its key. Key names: the desktop
takes Qt's key (the layout's letter); the web names a letter by the letter the layout types (Qt's rule: AZERTY's A is
`A`), else — a non-Latin layout — by its physical key, digits and punctuation by their physical key (US positions:
`Ctrl+Shift+,` stays `,`); a default registered by a web feature is checked by its own registered key, never by the
press's name. On macOS (web) a chord's ⌘ reads as Ctrl and Control as Meta (Qt's convention, so `Ctrl+K` is ⌘K), while
a modifier held alone keeps its own name (push to talk's `Ctrl` stays the Control key, as in 10.8). Web: `main` = the
whole page (in-page windows don't scope keys, as in 10.8). A held key repeats its action in both apps (defaults and a
person's keys alike, as in 10.8); a per-action repeat rule is a follow-up.

### 8.8 Settings → Shortcuts

`shortcutsView(app, doc)` → `{groups: [{group, label, items}], conflicts (the number of pairs), notes}`: every
assignable action, per group in `groups` order (empty groups left out), each group by folded label (§10.3) then id;
an item `{a, label, icon, keys (in effect), defaults, changed (the document has an entry), hold, clashes: [{key,
with: [action ids]}], browser (web: its keys the browser also uses — Tin Hat takes them while it has the focus)}`.
`setUserBinding(app, doc, action, keys | null)` → the document after one edit: `null` = back to the defaults (the entry
removed); a list = those keys (each checked, §8.4 — failures left out; duplicates once; at most
`limits.bindingsPerAction`); a non-empty list whose every key fails changes nothing (only `[]` = no key); an entry
equal to the defaults is removed (the action follows the table again — within a clash it then ranks as a default);
entries this app does not know are kept; keys of the document in code-point order; `null` when no entry is left (the
host removes the pref). An edit that would take the document past `limits.bindingsActions` entries or
`limits.bindingsBytes` (what a reader keeps, §8.5) changes nothing: the document is answered as it was. The palette's `hint`
(§10.1) is an action's first default key; the hosts show its first key in effect instead (the same rule both apps).

## 9. Rows

### 9.1 Row kinds

`rows."<island>.<row>"`: `{contexts, forms, look, scale, style, editable, doc, overrides?}`.
- `contexts` — the contexts the row provides (§3.2); `forms` — `desktop` and/or `phone` layout forms.
- `look` / `scale` — the row's defaults when the stored row has none (§9.4).
- `style` — how the host draws this row's buttons today: `header` (the round header buttons), `tool`
  (ThToolButton / ToolButton), `call` (the call bar's round buttons), `rail` (the nav bubbles), `hover` (a message's
  hover bar), `tile` (tile chrome). Informative: any host may draw any row in its generic action-button style.
- `editable` — the user may change the row in edit mode in 11.0: the room header, the composer, the account island,
  the call controls (desktop call bar, phone call bar, phone header) and your own `buttons` islands (DESIGN). The
  other rows are described by the table (and drawn from it once the hosts move over) but stay fixed.
- `overrides.<action id>` — how this row draws the action: `label`, `shortLabel`, `icon`, `tip`, `look`, plus
  `requires` (false ⇒ hidden in this row) and `when` (false ⇒ unavailable in this row), ANDed with the action's.
  The header's call button is hidden in a call (`requires: not call.in`) and dims while connecting (the action's
  `when`) — exactly today's behaviour.

Row kinds today: `nav.main`, `rooms.header`, `account.main`, `header.main`, `header.phoneStart`, `header.phoneEnd`,
`call.status`, `call.bar`, `call.tile`, `call.phoneBar`, `call.phoneTop`, `composer.start`, `composer.end`,
`timeline.hover`, `buttons.main` (every `buttons:<n>` island's row).

### 9.2 The stored row (layout)

A row lives in the layout: `opts.<island ref>.rows.<row id>` = `{look?: icon|iconLabel|label, scale?: S|M,
items?: [Item…]}` (LAYOUT.md §3.9: ≤ 8 rows per island, ≤ 24 items, unknown keys kept, repaired by the layout engine
§5.5), synced through the Matrix account with the layout. Item: `{a: <id>, target?: {≤ 4 keys}, hideWhenOff?: bool,
sepBefore?: bool}` — `hideWhenOff`: hide instead of dim while unavailable (DESIGN: "a per-button option hides it
instead"); `sepBefore`: a separator before it (the call bar's Leave). The row kind of `opts.<ref>.rows.<row>` is
`<kind of ref>.<row>` (`buttons:a1` → `buttons.main`). A row the layout does not hold falls back to the preset's
default row (§9.8).

### 9.3 Placing (`place(row, item)`, edit mode)

The first failure: `unknown-row`, `bad-item` (not an object with a string `a`), `unknown-action`, `context` (a
context-only action in a row that provides none of its contexts), `bad-flag` (hideWhenOff / sepBefore not a boolean),
then §5.6's. The answer's item is normalized: `{a, target?}` with the normalized target only when it is not empty,
flags only when true; other keys dropped.

### 9.4 Resolving a row (`row(app, snapshot, row kind, value, context?)`)

`look` = the stored look when it is one of icon / iconLabel / label, else the kind's; `scale` likewise (S / M);
the first `limits.rowItems` items, in order, each resolved to:

```jsonc
{"a", "known", "state": "shown" | "dimmed" | "hidden", "why", "label", "shortLabel", "icon", "tip",
 "look",            // the row's look, or the row kind override's
 "active", "danger", "primary", "pick", "hold", "subject", "subjectKind", "targetName", "targetIcon", "emoji",
 "target",          // the item's target normalized (§5.6), or null
 "split", "sepBefore", "hideWhenOff"}
```
`state`: not visible (§7.1) ⇒ hidden; not enabled ⇒ dimmed, or hidden with `hideWhenOff`; else shown. An item that
is not an object with an `a` of the item syntax ⇒ hidden, `why: "bad"`. The row answer: `{row, look, scale, style,
editable, items}`. Hosts draw `shown` and `dimmed` items; edit mode shows every item.

### 9.5 A newer Tin Hat's button

An `a` of the item syntax that this version does not know is **kept** (never removed or rewritten; the layout keeps
it too) and drawn as the placeholder: `known: false`, `why: "unknown"`, the table's `placeholder` label ("Needs a
newer Tin Hat"), icon and tip, state `dimmed` (or `hidden` with `hideWhenOff`). It never runs.

### 9.6 The drawer (`drawer(app, snapshot, row kind)`, edit mode)

Every action of the app that may go into the row — its contexts provided by the row (or none) and not hidden by
`requires` in this snapshot — per group in `groups` order (empty groups left out), each group by folded label
(§10.3, code-point order), then id: `[{group, label, items: [{a, label, icon, pick}]}]`.

### 9.7 Menus

`menus.<id>`: `{context?, label?, doc, items}`; an item is a row item plus `section?`, `label?`, `when?`,
`forms?`, `sub?` (the action's choices as a radio submenu), or `{menu: <id>}` (a submenu, shown when any of its
items is). `menu(app, snapshot, menu, form, context?)` resolves every item like §9.4. Menus are **not editable in
11.0**; the table describes them so both apps can draw them from one list.

### 9.8 Default rows

`default-rows.json`: `presets.<preset>.<form>.opts.<island>.rows.<row>` for the five presets (classic, compact,
callFirst, sideMonitor, handheld) × desktop / phone — today's rows, same order, same icons: the room header (Game
Reel, Calendar, Memories, Start/Join a call, Room info — Call & device settings left the header 2026-09-29 and lives in the call bar), the composer (Attach | Emoji, GIF,
Soundboard, Pinned, Send), the account island (Report a problem, Tuck nav into corner, Menu), the call bar (Mute,
Game chat / Leave the corner, Deafen, Camera, Share screen, Share audio, Stream health, Soundboard, Stop the sound,
Game / join code, Be right back, Call & device settings | Leave call), the call status line, the tile chrome, the
nav island, the room column's header and the message hover bar. They move into `layout.schema.json`
`x-tinhat.presets.<preset>.<form>.opts` together with the layout owner's vector regeneration (the layout contract is
not edited by this track).

## 10. The Ctrl+K palette

### 10.1 What it lists

One field over **rooms** (joined, not spaces), **invites** (pending invites to rooms and DMs, not spaces),
**people** (every person the snapshot lists but you) and **actions** (§10.2), ranked together (§10.5); Enter runs the
selection: a room opens, an invite **opens where it waits** with Accept / Decline (§14.3 — the palette never accepts or
declines it), a person gets a DM (`person.message`), an action runs (§14.1) — or, when it picks (§5.7), the palette
switches to **stage 2**: the choices of its target (§10.6). An empty query lists the pending invites (newest first),
then the rooms as Ctrl+K always did (the room you are in last). A leading prefix character limits the kinds: `>`
actions, `@` people, `#` rooms and invites (`palette.prefixes`; leading spaces do not hide it). Each action row shows
its icon, its current label (the toggle's face: "Mute" / "Unmute") and its first default key (`hint`). An invite row
shows the avatar and the name the room list shows for the invite (a DM invite: the inviter's name) and the marker
`palette.texts.inviteMarker` (the room list's "Invited" pill) — never an unread badge.

### 10.2 Which actions

An action is listed when it is in this app, placeable (no `contexts`), not `palette: false`, not `hold`, not
`pending`, and visible in the snapshot (§7.1). Unavailable ones are listed after every available match (a dimmed row
that does nothing), so "Leave call" outside a call still finds itself.

### 10.3 Folding

`fold(s)` = the Unicode default lower-casing of `s` (`String.prototype.toLowerCase` / `str::to_lowercase`), then
every run of separator code points (`palette.separators`, inclusive ranges: whitespace, ASCII punctuation, `·`,
general punctuation U+2010–U+2029, …) becomes one space, trimmed. Queries and texts are folded the same way. No
diacritic folding in v1 ("cafe" finds "Café" only as a subsequence). Lower-casing follows each runtime's Unicode tables
(both apps are on Unicode 17 today); a letter encoded after that may fold differently until both update.

### 10.4 Tiers

For a folded text `t` and a folded non-empty query `q`:
- **name**: `t` starts with `q` → `prefix` (100); `q` starts a word of `t` (`t` contains " " + q) → `wordStart` (80);
  `q` has two or more words and each starts some word of `t` → `words` (60); `t` contains `q` → `substring` (50);
  the code points of `q` (spaces skipped) appear in order in `t` → `subsequence` (30) — **only** for room, invite,
  person and choice names, never an action's longer labels; else 0.
- **keyword** (an action's keywords): prefix → `keywordPrefix` (70), word start → `keywordWordStart` (60),
  substring → `keywordSubstring` (40).
- **alias** (a room's or an invite's address, a person's user id): `t` contains `q` → `alias` (40).

An entry's **score** is the best tier over its names (rooms, invites and people: the name; actions: the current label, the
shortLabel, and the base label when a face changed it; choices: the label), keywords and aliases (a choice whose
label differs from its value: the value), plus its **boost** when it matched at all: rooms and invites `+unread` (15)
when `room.hasUnread`, `+dm` (10) when `room.isDm` — an invite is matched and ranked like a room.

### 10.5 Ranking

Entry order: invites (room subjects with `room.invited` true and `room.joined` not) in `lists.invite` order, rooms
(`room.joined` true) in `lists.room` order (for either list: else room ids in code-point order; either way only ids
whose subject entry is an object); actions in the **catalogue order** (`groups` order, then the folded base label,
then id); people in `lists.person` order; choices in their stage order. An entry is **last** when it is the room you
are in (`current.room`), or an unavailable action or choice. Empty query (all or room mode): the invites, then the
rooms — last ones after the rest, else in entry order. Otherwise the entries with a score > 0, sorted by (last,
score descending, kind in `palette.kindOrder` = invite, room, action, person, choice, entry order) — an invite and a
room of the same name and score: the invite first, as on the empty list; at most `maxResults` (100) are returned,
`total` counts them all. Output: `{mode: all|room|person|action|stage, query (the folded query), stage (the picked
action or null), total, items: [{kind, id, label, icon, hint, enabled, pick, active, emoji, a, target, score}]}`
(`kind` = invite | room | action | person | choice; `a` = the action a row runs, `target` = a choice's target,
`active` = an action's or a choice's toggle state — stage 2 marks the theme / layout in use — null for invites, rooms
and people; an invite's `icon`, `hint`, `a` and `target` are null).

### 10.6 Stage 2 — picking a target

`palette(app, snapshot, query, stage: <action id>)` lists the action's choices (a listed action with a target):
- a device-local kind (`absent: pick`): this device's subjects of the kind in `lists.<picker>` order (`inputs`,
  `outputs`, `cameras`, `audioSources`; else all subjects of the kind), target `{<key>: id}` (transient, §5.2);
- a stored kind with `absent: pick`: the listed values (`target.values`, else the value type's) with their labels
  and icons, then — when the value type has no fixed list or has an `or` — the snapshot's subjects of the kind (rooms
  and spaces you joined, people but you) in list order, target `{<key>: value}`;
- else the first required enum param (code-point order), target `{<param>: value}`;
- nothing to pick ⇒ no choices. Each choice is evaluated with its target (§7, transient): not visible ⇒ left out,
  unavailable ⇒ last. Ranking as §10.5 with the choice labels (and values as aliases).

### 10.7 Texts

`palette.texts`: the field's placeholder, stage 2's (`{label}` = the action's label), the empty-result line
(`{query}` = the query as typed), the empty room list, an invite row's marker (`inviteMarker`: "Invited", the room
list's word) and the section names per kind.

## 14. Running actions (per app; informative, parity required)

### 14.1 The executor

Each app maps every action id of its `apps` to the command it already has (web `src/actions/exec*.ts`, desktop
`ActionsExecutor.qml`): the call controller's mute toggle, the calendar window, the soundboard's play… Running an
action from any surface (row button, palette, a key) first presents it (§7): not enabled ⇒ nothing; `pick` ⇒ its
picker (palette stage 2 or the host's); `confirm` ⇒ the confirm dialog; then the command with the resolved subject
and params. Context-only actions are run by the surface that provides their context (it passes the context).

### 14.2 The snapshot providers

Each app builds §4.3's snapshot from its real state: global values from its stores / controllers, the current room's
subject values, and (for the palette) the room, people, space, theme, sound and device lists. A value the app cannot
know stays absent (its rule is false).

### 14.3 Hosts

Web: `ActionButton` / `ButtonRow` (`src/actions/ui/`), the palette in `features/nav` (Ctrl+K, extends the quick
switcher). Desktop: `ActionButton.qml` / `ButtonRow.qml`, the palette in `QuickSwitcher.qml`, the
`ActionsController` (cxx-qt, every QML-facing function `#[qinvokable]`). Colours only from theme tokens (`action.*`
and the existing button / switcher tokens; an invite row's marker is the room list's pill, `rooms.pill.invite.*`).
Ctrl+K on an invite (Enter or a click, both apps): the palette closes and the invite shows where it waits with Accept /
Decline — its room list row: the rail switches to People (a DM invite) or Home (a room invite) unless the list on
screen already holds the row, a tucked nav's drawer opens, phones show the list page, and the row scrolls into view.
Nothing is accepted or declined. The room picker built on the palette (pick mode, "Share to a room…") lists joined
rooms only.

## 15. Decisions

Coordinator (2026-09-26, research §14): object-first ids, `group` is metadata; `requires` hides, `when` dims; menus
share the item lists but are not editable in 11.0; device-local targets and bindings never sync; destructive actions
may go into button islands, always behind their confirm; curated toggles, no generic `settings.set`; `call.micCheck`
and `layout.edit` added, no message search ("search" = the palette); default rows live in the layout presets.
Buttons track (2026-09-27): unknown ids are kept and drawn as the placeholder (§9.5); row overrides may carry
`requires`; the palette's ranking, prefixes and stage 2 (§10); the palette lists unavailable actions last. S7-C2
(2026-09-28): the shortcut engine (§8.3–§8.8): a person's keys live in the device pref `shortcuts`; a key given to
another action takes it from its default owner (dispatch order, flagged as a clash, never refused); push to talk
takes a modifier held alone or an F-key (the research's "a chord cancels a bare-modifier hold" rule is NOT applied in
11.0: both apps keep today's hold behaviour); holds are watched by their hosts, never matched. A second-opinion review
of the engine (S7-C2) changed: a list whose every key fails no longer takes the defaults away (read and edit), an edit
past the document's limits changes nothing, `matchKey` leaves a clash's loser out (as the hosts do), a trailing `+` key
survives spaces around the text, the validator keeps assignable actions to `app` / `main` scopes without params, and
the web checks a feature's default by its registered key and names letters the way Qt does. Kept as they are
(documented above): a clash is decided over overlapping scopes, not per press; an entry equal to the defaults is
removed; macOS chords swap ⌘/Control while a held modifier keeps its name; a held key repeats; a newer version's
document is replaced by the first edit.

**Product decisions (2026-09-27), one named constant per app each** (web
`src/actions/decisions.ts`, desktop `ActionsHost.qml`; flip both apps together): (1) **Rec and Clip act on the call's
room** — the call's own rows supply the call's room as their context even while another room is on screen
(`REC_CLIP_ROOM` / `recClipRoom` = "call"); (2) **the call controls dim while a call is connecting** — the call rows
read the snapshot as it is (`call.in` false until connected); the other value reads "connecting" as "in the call"
(`DIM_CALL_CONTROLS_WHILE_CONNECTING` / `dimCallControlsWhileConnecting`); (3) **Ctrl+K lists people you have DMs
with** — the palette's person list is your DM partners (`PALETTE_PEOPLE` / `palettePeople` = "dmPartners"; the
other value, "roomMembers", also lists the members of the room on screen). Also: the web keeps switching to the
phone layout below 700 px.

**2026-09-28: Ctrl+K lists pending invites again** (10.8.1's desktop switcher listed
them first; 11.0's palette had joined rooms only) — in both apps: the kind `invite` (§10.1, §10.5; `lists.invite`,
§4.3), ranked like rooms and before a room on a tie; the row reads as an invite (`palette.texts.inviteMarker`, no
badge); Enter opens the invite where it waits (§14.3), never accepts or declines it. Space invites are not listed (joined
spaces are not either; the rail shows them). With invites listed, the person list of decision (3) is your JOINED DM
partners — a pending DM invite is its invite row, not a person too (its Enter would start a DM beside the invite).

Buttons (S7-C, 2026-09-27): game chat and "Leave the corner" share one slot of the call bar, so each is hidden by
`requires` while the other applies and only dims (`when: call.in`) while the call connects — no button vanishes and
comes back while connecting; "Share audio" applies in every call (a press without a remembered source opens the share
popover). Until edit mode wires the synced layout document (LAYOUT.md §9), each app keeps the device's layout forms —
the rows (§9.2) and your own button islands — in the device prefs `layout-desktop` / `layout-phone`, stored exactly
as the document will carry them (the widget list's precedent).

10.8.1 (S7-C2, 2026-09-28): "Save GPU while Tin Hat isn't focused" became the master switch of every unfocused rule
(GPU.md §1 amendment), default OFF, in Settings → Appearance → Performance of both apps. `call.unfocusedSaver.toggle`
follows it: group `app`, both apps, the Settings hint as its tip; `prefs.callUnfocusedSaver` is the shared rule
`unfocusedSaverOn` / `unfocused_saver_on` of the pref `call-unfocused-saver` ("1" / "true" = on, absent = off — never
read with a default of on). The id keeps its first name. `app.gifAutoplay.toggle` is in both apps (10.8).

**2026-09-28 (11.0.2): the call buttons' hiding is an easy toggle.** The call bar
(desktop form) shows while the pointer moves over the call and hides 3 s after it stops (0.8.33, both apps).
`call.bar.pin.toggle` ("Keep call buttons visible" / "Let call buttons hide", group `calls`) turns that off: pinned,
the bar stays shown in a call whatever the pointer or the window focus (the tile buttons keep hiding; the muted-talk
bubble still brings an unpinned bar up). Three ways, one preference: the bar's own pin (a small round button after
Leave, behind a divider; its tooltip = the action's short faces "Keep buttons visible" / "Let buttons hide", pressed

someone pins it). Hidden on phones (`requires: not ui.phone`): the phone call screen never hides its bar by itself (a
tap shows / hides it). A pinned bar draws nothing while it sits there (GPU.md: no animation, no timer of its own).
