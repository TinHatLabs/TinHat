## 1. JSON data

**1.1 Reading.** Every JSON text (account data, a vector's `text`) is read with the colour contract's reader
(ENGINE.md §9; web `readJson` = `JSON.parse(toWellFormed(text))` + `isJsonData`, Rust `json.rs parse_json`): strict
ECMA-404 (no BOM, comments, trailing commas, `NaN`); arrays/objects nested at most **128** deep (the root container is
level 1); a `\u` escape that leaves a lone UTF-16 surrogate is refused (a raw lone surrogate in the text reads as
U+FFFD); duplicate keys: the last wins; `__proto__`, `constructor`, … are ordinary keys; a number that overflows a
double reads as **null**. Anything else is "not JSON data".

**1.2 Values.** Objects hold own keys only (the TypeScript reference builds them without a prototype). An **integer**
is a JSON number whose value is integral (`1.0`, `1e2` and `-0` are integers; `1.5` is not). A known integer field
holding anything else is invalid (never rounded).

**1.3 Canonical form** (the colour contract's `canonJson` / `canon_json`): object keys sorted by code point (= UTF-8
byte order = Rust `str` order), no whitespace, numbers printed as ECMAScript `Number::toString` (`1.50` → `1.5`, `-0` →
`0`, `1e21` → `1e+21`), strings escaped like `JSON.stringify`. "Equal canonically" means equal canonical text. The
vector files are the pretty variant (`prettyJson` / `pretty_json`: 2-space indent, `": "`, one element per line, `[]` /
`{}` when empty, final newline). Byte sizes are UTF-8 bytes of the canonical form. **Lengths of strings** (names,
device ids, preset names) count **code points** everywhere (the schema's `maxLength` counts the same).

**1.4 The input domain and the budgets.** Every public function takes **JSON data** (§1.1: what the reader can produce
— acyclic, nested at most 128 deep, no lone surrogates, finite numbers); a runtime value outside it (a cycle, a function,
`NaN`, a typed array, a map) is answered like text that is not JSON: repair → Classic with `replaced-by-classic
not-json`; an operation or a save → `bad-op: bad request`; solve and drop zones → as for an empty form / no zones;
readDoc → ignore. The data check comes **first** and is itself bounded (it stops at depth 129, which also ends any
cycle); only then are canonical sizes computed. Budgets: a desktop or phone form 8192 canonical bytes (§3.10, §5.6);
a document 1 MiB canonical and 1024 entries to be read at all (§9.2), 65,536 bytes to be written by a save (§9.6);
the view state at most 256 keys per map (`sizes`, `active`, `popouts`; the first 256 in code-point order) and 64
`forceCollapse` refs (after removing repeats); `content` at most 256 refs (the first 256 in code-point order). Every
loop of solve is bounded by the form's limits (64 nodes, 16 steps, 8 floats): the collapse fixpoint runs at most 16
rounds (§7.5), a distribution at most one run per child (§7.6).

## 2. Registry and identifiers

**2.1 The registry** is the schema's `x-tinhat` block: `islands` (per kind: `presence`, `hideable`, `required`,
`stackable`, `floatable`, `popout`, `maximizable`, `multi`, `phone`, `pref {w, h}`, `min {w, h}`, `orientH {pref,
min}`, `float {w, h}`, `bar` (the call's control-bar height, layout units), `collapse` (allowed step `to`s), `home`
(placement rules), `group`, notes), `limits`, `bounds` (incl. `shapeMin`), `shapeDefaults`,
`presets` (classic, compact, callFirst, sideMonitor, handheld), `internalPresets` (`classic-flush`), `errors`,
`repairNotes`, `informationalNotes`, `regionOrder`. It is data; nothing iterates it in JSON key order — every ordered
walk uses **region order**: `nav, dms, spaces, rooms, widgets, account, header, call, timeline, composer, panel, buttons`.

**2.2 Syntax** (whole string): **island ref** `[a-z][a-zA-Z0-9]{0,23}` optionally followed by `:[a-z0-9]{1,12}`;
**id** (layout, container, stack, float) `[a-z][a-z0-9-]{0,31}`; **collapse step ref** `[a-z][a-zA-Z0-9-]{0,31}`
optionally followed by `:[a-z0-9]{1,12}`; **node type** `[a-z]{1,16}`.

**2.3 Known, unknown, compat refs (Q-KNOWN).** A ref is **known** iff its kind (the part before `:`) is a registry kind
and it has an instance exactly when the kind is `multi` (`rooms`, `buttons:a1` known; `buttons`, `rooms:x` unknown).
Every other well-formed ref is an **unknown island**: kept in storage, never rendered, never moved or removed by this
version; its `size` (and any other key of its leaf) is opaque — any JSON value, kept verbatim, never checked. Refs starting with `_` (`_nav`, `_room`) are the **compat islands** of the internal migration preset: solve
treats them as always present with no registry minimum; they never pass repair (syntax) and are never stored.

**2.4 One namespace, reserved ids.** Island refs and container / stack / float ids share one namespace (operations,
view-state maps and drawer ids use it). A container, stack or float id must not equal a registry kind (`buttons`
included), `emergency`, start with `overflow-`, or equal any island ref of the form.

**2.5 Region order** (fixed logical order for Tab, F6, screen readers, the web host's DOM order): §2.1's list;
`buttons:*` instances in code-point order of their refs. Independent of the layout (ISLANDS-ARCH §2.7).

## 3. Forms

**3.1 The desktop form** is an object. Known keys: `root` (a row or col), `floats` (array), `hidden` (array),
`collapse` (array), `opts` (object), `preset` (string ≤ 32 code points, informational), `gap` (integer 0-32), `margin`
(integer 0-64), `density` (`compact | normal | touch`, host only). Unknown keys are kept.

**3.2 Nodes.** Every node is an object with a string `t` of node-type syntax.
- **row / col** (containers): `id`, `c` (children, left→right / top→bottom), optional `size`, optional `gap` (integer
  0-32, this container's children). Known keys `t id c size gap`.
- **stack** (tabs; children are island leaves only): `id`, `c`, optional `size`, `active` (a child's ref). Known keys
  `t id c size active`.
- **island** (leaf): `i` (ref), optional `size` (§3.3 for a known ref; opaque for an unknown one, §2.3). Known keys `t i
  size`.
- **unknown node type** (any other `t`): opaque — kept with every key; if it has an array `c`, those children are
  repaired, traversed and count as placed; it is never removed, unwrapped or edited by normalization and is read-only
  to operations; solve renders it as a col of its children (§7.3).
- **Hidden leaf** (entries of `hidden`): an island leaf plus optional `from: {parent: id, index: 0..15}` (where it was
  hidden from). Known keys `t i size from`.
- A node **carries unknown keys** when it has a key outside its known set or its `size` has a key outside §3.3's set.

**3.3 Sizes** (along the **parent's** axis only; known keys `fixed share auto pm min max minPm maxPm grow`):
at most one **basis** — `fixed` (layout units 0-8192), `share` (weight 1-10000), `auto: true` (content size), `pm`
(per mille 0-1000 of the parent's inner length) — plus optional `grow` (1-10000, only next to a `fixed`/`auto`/`pm`
basis), `min`, `max` (0-8192), `minPm`, `maxPm` (0-1000); `max ≥ min`, `maxPm ≥ minPm`; the `minPm` of one
container's children add up to at most 1000. **Effective size** (what solve and the operations read, Q-NOBASIS): a
stored size with a basis is used as stored; otherwise an island (known, not compat) takes its registry `pref` for that
axis (basis and constraints; `orientH.pref` when `opts.<ref>.orient = "h"` and the registry has `orientH`), and a
container / stack / compat island `{share: 1}`; the stored constraints (`min max minPm maxPm`) then replace the same
keys. Inside a stack, children's sizes are kept but ignored.

**3.4 Floats** (`floats`, at most 8): `id`, `anchor` (`tl t tr r br b bl l`), `dx`, `dy` (integers −4096..4096, inward
positive, absent = 0), `w`, `h` (float sizes: at most one of `fixed | auto | pm` — pm of the host —, no `share`, plus
`min max minPm maxPm`; no basis = auto; the key absent = the registry `float` size of an island node, `{auto: true}`
for a group), `reveal` (`always | hover`, absent = always), `node` (an island or a group). A float holding a required
island is never `hover`.

**3.5 Collapse steps** (`collapse`, at most 16): `ref` (a container / stack id or an island ref of the root tree),
`to` (`fold | hide | overlay | drawer`), optional `below` (layout units), optional `w` (drawer panel width). An island
step's `to` must be in its registry `collapse`; containers and stacks allow `hide overlay drawer`. **Safety:** a step
whose subtree (in the form) holds a room-group island (header, timeline, composer) or the call is not allowed.

**3.6 The room group.** **R1** timeline and composer are adjacent children of one col (either order). **R2** the
header, when placed, is the first or last child of the timeline's col or of an ancestor col of it. **R3** none of the
three is in a stack or a float; only the header may be hidden. `opts.composer.composerTop` and
`opts.header.headerBottom` **record** the tree's order (N9); they are derived, never set directly (Q-N9).

**3.7 Placement rules** (every valid form, and an operation's mutated copy before normalization): one occurrence per
island ref across root, floats and hidden; hidden islands hideable and not required; stacks hold island leaves only,
known ones stackable; islands inside floats floatable, and no required island in a `hover` float; timeline, composer
and call placed (root or floats; timeline and composer in the root); R1; the header not in a float, R2. Error mapping
for operations in §8.1.

**3.8 Home rules** (registry `home`, first applicable wins; repair and `restore`): `{beside: X, side, container?}` —
X must be a known island placed in the root tree outside unknown nodes; the target is X, or with `container: true` X's
parent (unless that is an unknown node); the island is inserted as `dockBeside` would (§8.2); `{edge: side}` — as `edge`;
`{groupEdge: top|bottom}` — first / last child of the **group-edge col** = the nearest col that contains the timeline's
col, else the timeline's col itself. A rule applies when its target exists and the result keeps the placement rules
(repair checks only: no ref twice in the root tree and the floats, stacks hold known-stackable islands only, no known
non-floatable island in a float, R1 when timeline and composer are placed, R2 when the header is placed and the
timeline's col exists). **Fallback** when none applies: a new root
`{t: <axis>, id: n<k>, c: [island, oldRoot]}` (or `[oldRoot, island]`) on the side of the island's last `edge` rule
(left when it has none), the old root's size replaced by `{share: 1}` (its unknown size keys kept) (Q-HOMEFALLBACK).
Inserted leaves keep the size they have (repair's new leaves have none).

**3.9 Options** (`opts`, at most 32 entries of which at most **30** are neither `composer` nor `header` — the two
entries where N9 records the room order always fit; keys island refs, values objects of at most 32 keys of which at
most **30** are neither `composerTop` nor `headerBottom`): known keys
`compact` (boolean), `orient` (`v | h`), `composerTop`, `headerBottom` (booleans), `widgets` (array of at most 12
objects `{w: [a-zA-Z][a-zA-Z0-9]{0,31}, size?: S|M|L, settings?: object ≤ 16 keys}`), `rows` (object of at most 8
rows `{look?: icon|iconLabel|label, scale?: S|M, items?: array ≤ 24 of {a: [a-z][a-zA-Z0-9.]{0,63}, target?: object
≤ 4 keys, hideWhenOff?: boolean}}`). Unknown keys kept.

**3.10 Limits** (`x-tinhat.limits`; checked in this order, the first exceeded names the limit). The **walk**: from
`root` and from the `node` of every object in `floats`, every object reached through the `c` arrays of any object
(islands' own `c` too), the start at depth 1. Canonical bytes of the form ≤ 8192 (`too-large`); walk depth ≤ 8
(`too-deep`); objects walked ≤ 64 (`too-many-nodes`; hidden not counted); every walked `c` array ≤ 16
(`over-limit-children`); a walked object with `t: "stack"` has `c` ≤ 8 (`over-limit-tabs`); `floats` ≤ 8
(`over-limit-floats`); distinct strings starting with `buttons:` among the walked objects' `i`, the hidden strings and
the hidden objects' `i` (no syntax check) ≤ 8 (`over-limit-buttons`); `hidden` ≤ 32 (`over-limit-hidden`); `collapse`
≤ 16 (`over-limit-collapse`). Document (§9): a save writes at most 65,536 bytes and 12 live layouts; tombstones and
conflicts are never dropped (bounded by the size); a version vector holds at most 16 counters; a document is read only
up to 1 MiB and 1024 entries.

**3.11 The phone form**: `rail` (≤ 16 refs), `list` (≤ 16), `hidden` (≤ 32), `opts` (§3.9). A known island belongs
to the column its registry `phone` names (nav, dms, spaces → rail; rooms, widgets, account, buttons → list; the room
group, panel and call are no phone sections) and appears at most once across rail, list and hidden.

## 4. Normalization

Runs as repair's last step and once after every operation; idempotent. It never removes or unwraps a node that carries
unknown keys (its known fields are still fixed by N4 / N6), never edits unknown node types (their children are
normalized) and never hoists an unknown island (Q-N1N3). Notes (repair only) in parentheses. **Order of the passes**
(and so of their notes): N1-N3 on the root tree, N5, N1-N3 on each float's node in float order, N4, N6, N7, N9. "Every
node in order" below = pre-order of the root tree, then of each float's node in float order.

- **N1-N3** (post-order over the root tree, then each float's node): a row / col / stack with no children and no
  unknown keys is removed (`empty-container-removed <id>`) — never the root; one with a single child and no unknown keys
  is replaced by that child when the child is a known node type, not an unknown island, its size carries no unknown
  keys, and (for the root) it is a row or col (`single-child-unwrapped <id>`). The child takes the container's size
  (`{share: 1}` when the container had none; for the root: the root's size, else none) (Q-N2SIZE). A float whose node is
  gone is removed (`bad-float-fixed <float id>`, or `#<index>` — the index at that moment — when its id is not a
  string).
- **N5** the root is a row or col: anything else is wrapped in `{t: "row", id: body}` (`body1`, `body2`, … when taken)
  (`root-wrapped <id>`).
- **N4** every stack in order: an **empty** stack (kept for its unknown keys, N1) has no `active` — a present one is
  removed; otherwise its `active` names one of its island children, else it becomes the first child's ref (either
  fix: `bad-field-fixed <id>`). An empty stack without `active` normalizes unchanged.
- **N6** first every node in order that has a `size` (known types, not unknown islands), then every hidden leaf (not
  unknown refs): §5.3's size fix (`bad-size-fixed <key>`); then every row / col in order: the `minPm` of its children of
  a known type that are not unknown islands; while their sum exceeds 1000, `minPm` is removed from the last such child
  backwards, skipping children whose `minPm` is 0 or absent (`minpm-capped <container id>`, once per container).
- **N7** hidden: an entry whose ref is placed or already listed leaves (`dropped-duplicate <ref>`); a `from.parent`
  that N2/N3 remapped follows when the replacement is a row / col / stack of the form (a replacement island leaves the
  old value — a stale hint; restore never accepts an island). Collapse, in order: the ref follows the remap; a step whose ref no longer names a known
  node of a known type in the root tree (islands, unknown islands and nodes inside unknown nodes included), or whose
  `to` that node does not allow (`fold` on a container / stack, or outside a known island's registry list; an unknown
  island's `to` is never checked), is dropped (`bad-collapse-dropped <ref>`); a repeated ref is dropped
  (`dropped-duplicate <ref>`).
- **N8** new ids: `n<k>` containers, `s<k>` stacks, `f<k>` floats, k = the smallest positive integer such that the id
  is not used by any node or float `id` or island `i` anywhere in the form (for an operation: the form before the moved
  node was detached).
- **N9** when R1 holds: `opts.composer.composerTop = true` if the composer comes first, else the key is removed (and
  `opts.composer` too if that emptied it); when the header is placed docked in a col: `opts.header.headerBottom = true`
  if it is the last of several children, else removed — and `opts.header` too if that emptied it
  (`opts-fixed <composer|header>`). `opts` is created only to set a flag and is never removed.
- **Remap**: every N2/N3 replacement records `old key → new key` (chains collapse: a → b → c gives a → c); operations
  return it (sorted) so the host can move its device-local view-state keys (`forceCollapse`, `sizes`, `active`,
  `drawer.open`).

## 5. Repair and validation

**5.1 repair(desktop value) → {form, notes}** — any value; never throws; the input is never modified; the result is
a valid form (§5.4) — the **projection**. A note is the string `"<note> <subject>"`, emitted in the order below.

1. Not an object → Classic (`replaced-by-classic not-object`); no object `root` with a node-type `t` → Classic
   (`… no-root`); over a limit (§3.10) → Classic (`… <limit>`). (Text input that is not JSON data: `… not-json`.)
   Classic = a copy of `x-tinhat.presets.classic.desktop`.
2. **Walk** (on a copy):
   a. form fields in the order `preset gap margin density floats hidden collapse opts`: invalid → dropped, integers
      clamped (`bad-field-fixed <key>`); `floats` / `hidden` / `collapse` that are not arrays are dropped; `opts`
      per §5.5 (`bad-opts-fixed …`).
   b. the root: not a row / col → wrapped per N5 (`root-wrapped <id>`).
   c. the root's own id / gap / size / `c` (as for any container), then its children depth-first, then each float
      (not an object → `dropped-invalid floats`; its id (§5.2, prefix `f`); its `node` walked like a child with the
      float's id as the parent subject — a `node` that is not a node, or that the walk drops (after the walk's own
      note), drops the float: `bad-float-fixed <id>`), then `hidden`. Per child (subject for dropped children = the parent's id, or its `t` for
      an unknown node):
      - not a node (not an object, no node-type `t`) → dropped (`dropped-invalid <parent>`);
      - island: a ref that fails the syntax → dropped (`dropped-invalid <parent>`); a ref seen before (root, then floats,
        then hidden) → dropped (`dropped-duplicate <ref>`); an unknown ref → kept (`unknown-island-kept <ref>`,
        informational; its size is not touched); a known ref → size fixed (§5.3, `bad-size-fixed <ref>`);
      - row / col / stack: id (§5.2), then `gap` (rows / cols; `bad-field-fixed <id>`), size (`bad-size-fixed <id>`),
        `c` not an array → `[]` (`bad-field-fixed <id>`), then the children;
      - unknown type: `unknown-node-kept <t>` (informational); an array `c` is walked, anything else left alone.
      Hidden entries: a string of ref syntax, not seen before, becomes a leaf (`hidden-upgraded <ref>`, then
      `unknown-island-kept <ref>` when unknown); seen → `dropped-duplicate <ref>`; an island-leaf object (`t: "island"`,
      `i` of ref syntax) is kept (seen → `dropped-duplicate <ref>`; unknown → `unknown-island-kept <ref>` and its size is
      not touched; known → size fixed; then `from` that is not `{parent: id-syntax, index: integer}` → dropped, an index
      outside 0-15 clamped, `bad-field-fixed <ref>`); anything else → dropped (`dropped-invalid hidden`). The subjects of
      a container's own notes and of its dropped children are its id **after** §5.2.
3. **Stacks** (every stack of the root tree and the floats, in pre-order of the form as it was before this step — a
   stack inside a moved-out group is visited in its own turn): children that are not islands, and known islands whose
   registry is not stackable, are collected **in their order** (`unstacked <key or t>` each) and spliced as one run
   directly after the stack in its parent (A, B stay A, B); a stack that is a float's node first becomes the first child
   of a new col `n<k>` that becomes the float's node, the run after it (Q-STACKFLOAT). Unknown islands stay.
4. **Room group**:
   a. timeline: in `hidden` → removed from it, its `from` dropped (`unhid-required timeline`), and placed by home rules;
      in a float → detached (`regrouped-room timeline`) and placed by home rules; missing → a new leaf placed by home
      rules (`restored-required timeline`).
   b. composer: in `hidden` → removed, its `from` dropped (`unhid-required composer`); missing → a new leaf
      (`restored-required composer`); placed but R1 fails → detached (`regrouped-room composer`); in each case it is then
      inserted directly after the timeline with `dockBeside`'s **insertion** only (§8.2: after the timeline when its
      parent is a col, else the timeline is wrapped in a new col `n<k>` that takes its size while it gets `{share: 1}`);
      the composer keeps the size it has (no pref rule).
   c. header: placed in a float or violating R2 → detached (`regrouped-room header`) and made the first child of the
      group-edge col (§3.8).
5. **Required and missing**: the call in `hidden` → removed, its `from` dropped (`unhid-required call`), and placed by
   home rules; missing → a new leaf placed (`restored-required call`); then every other non-multi registry island that is neither placed nor hidden, in
   region order, is placed by its home rules (`restored-missing <ref>`, Q-MISSING).
6. **Float fields** (per float, in order): `anchor` absent or invalid → `tl`; `dx`, `dy` non-integer → dropped, else
   clamped to ±4096; `w` / `h` invalid (not an object, `share`, two of `fixed auto pm`, `auto` other than true, a
   non-integer `fixed pm min max minPm maxPm`) → dropped (= the registry float size), else fixed like a size (§5.3,
   which also handles a stray `grow`); `reveal` present and invalid → `always` — any of these: one `bad-float-fixed
   <id>`; then `hover` with a required island inside → `always` (`reveal-fixed <id>`).
7. **Collapse steps** (in order): not an object, a ref of wrong syntax or an unknown `to` → dropped
   (`bad-collapse-dropped <ref>`, the subject `collapse` when the ref is not a string of step-ref syntax); the ref not a known node of the root tree → dropped
   (`bad-collapse-dropped <ref>`); an island step whose `to` the registry does not allow (unknown islands: kept), or
   `fold` on a container / stack → dropped (same note); unsafe (§3.5) → dropped (`collapse-unsafe-dropped <ref>`); a
   repeated ref → dropped (`dropped-duplicate <ref>`); `below`, `w` non-integer → dropped, else clamped 0-8192
   (`bad-field-fixed <ref>`).
8. **Normalize** (§4), its notes appended.
9. The result over a limit (repair can add nodes) → Classic, and the notes are **replaced** by the single
   `replaced-by-classic <limit>`. The options limits of §3.9 cannot be exceeded here: §5.5 reserves the room for N9's
   two derived entries and flags. A form replaced by Classic is **quarantined** by the next save (§9.5), never silently
   overwritten.

No clamping to the window here: stored sizes stay as the user set them; solve clamps.

**5.2 Ids** (walk order). Two sets, taken after step 2a: **used** = every string `id` and every string `i` of every
object reached from `root` and from each float's `node` through `c` arrays (not descending into islands), every float's
string `id`, every hidden object's string `i` and every hidden string — plus the ids assigned so far; **refs** = the
same objects' string `i`, the hidden strings and the hidden objects' `i` (no syntax check). A container / stack / float
id: not id syntax → `id-reassigned <new id>`; a reserved id (§2.4) → `renamed-reserved-id <old id>`; an id seen earlier
in the walk or in **refs** → `id-reassigned <new id>`; new ids per N8 (`n`, `s`, `f`) against **used**.

**5.3 Size fix (N6)** on a copy: a known integer field that is not an integer is dropped; integers clamped to their
ranges (§3.3); `auto` other than `true` dropped; several bases keep the first of `fixed, share, auto, pm`; `grow` with a
`share` basis or without a basis dropped; `max < min` → `max = min`; `maxPm < minPm` → `maxPm = minPm`. A size that is
not an object is dropped. Unknown keys kept.

**5.4 validate(form) → violations** = the notes repair would produce, **without** the informational ones
(`unknown-island-kept`, `unknown-node-kept`). A form is **valid** iff that list is empty; then repair returns it
unchanged. Every operation's result must be valid; the `validate` vectors cover each rule.

**5.5 Options fix** (desktop and phone): `opts` present but not an object → removed (`bad-opts-fixed opts`); else its
entries in code-point order of their keys: a key that is not a ref → dropped (`bad-opts-fixed opts`, one note per such
key); a value that is not an object → dropped (`bad-opts-fixed <ref>`); inside: `compact`,
`composerTop`, `headerBottom` not booleans, `orient` not `v|h`, `widgets` not an array, `rows` not an object → dropped;
widget items that are not objects with a valid `w` dropped, a bad `size` / `settings` dropped, more than 12 → the
first 12; rows: a row that is not an object dropped, bad `look` / `scale` dropped, `items` not an array dropped, items
without a valid `a` dropped, a bad `target` / `hideWhenOff` dropped, more than 24 items → the first 24, more than 8 rows
→ the first 8 in code-point order; more than 30 keys other than `composerTop` / `headerBottom` → the first 30 of those
in code-point order (the two flags are kept) — any change: one `bad-opts-fixed <ref>`. More than 30 entries other than
`composer` / `header` → the first 30 of those in code-point order (`bad-opts-fixed opts`; `composer` and `header`
are kept). So N9's derived entry and flag always fit, and repair's result never breaks §3.9 (Q-OPTSCAP).

**5.6 The phone form: repairPhone(value) → {form, notes}**: not an object → the Classic phone form
(`replaced-by-classic not-object`; `not-json` for text); over 8192 bytes → Classic (`… too-large`). Then `rail`,
`list`, `hidden` in that order (present but not an array → `bad-phone-fixed <key>`, read as empty): an item that is
not a ref → dropped (`bad-phone-fixed <key>`); seen before → dropped (`dropped-duplicate <ref>`); unknown → kept where
it is (`unknown-island-kept <ref>`); a known ref with no phone column → dropped (`bad-phone-fixed <ref>`; it is not marked seen, so each occurrence gives
that note); a known ref
in the other column → moved to the end of its own (`bad-phone-fixed <ref>`; misplaced refs are appended after the walk,
rail's then list's, in walk order). Then every non-multi island with a phone column that was not seen is appended to
its column in region order (`restored-missing <ref>`). **Overflow** (nothing known is ever dropped, Q-PHONEFIX): while
`rail` (then `list`) holds more than 16 refs, its **last unknown ref**, else its last `buttons:*` section, moves to the
end of `hidden` (`bad-phone-fixed <ref>`); while `hidden` holds more than 32, its last unknown ref, else its last
`buttons:*` section, is dropped (`bad-phone-fixed <ref>`) — the only case where repair loses an unknown ref, and only
for a form that already broke the limits. `rail`, `list`, `hidden` are written back (a key that was absent stays absent
while empty); `opts` per §5.5; finally the result over 8192 bytes → the Classic phone form (the notes replaced by
`replaced-by-classic too-large`). The result is a fixed point: repairing it again gives no note. `validatePhone` = its
notes without the informational ones.

## 6. View state and migration

**6.1 Fields** (device-local, never synced): `roomOpen`, `callShown`, `panelOpen`, `maximized` (an island ref or null;
only a registry-`maximizable` island counts — today only the call), `forceCollapse` (refs; today's corner mode = `["navcol"]`), `sizes` (per node key a size
override), `active` (per stack id the active tab), `drawer {open: drawer id | null, pinned}`, `popouts` (per island
its window geometry `{x, y, w, h, screen}`), `layoutId`, `legacyCallPaneFm`.

**6.2 Rules.** One drawer is open at a time (`drawer.open` names a collapse drawer by its ref — a merged drawer by any
of its refs —, a hover float by its id, `emergency`, or `overflow-<container key>`); `pinned` is host behaviour. A
`sizes` override is **merged** into the effective size (§3.3): an override with a basis removes the stored basis and
`grow` and sets its own (and its `grow`); its `min max minPm maxPm` replace the stored ones; the override is read like a
stored size (§5.3); it applies only while its node is present, never in the emergency arrangement and never inside an
overflow panel (§7.9). Outside edit mode only the call/chat seam writes one (`{call: {pm}}`, the host clamps it to
200-850). An island named in `popouts` is absent from the main window's solve (Q-POPOUT) — only when its registry
allows pop-out (`popout: true`); other names are ignored, so no required island can be popped out of reach (Q-CAPS). On Done, overrides of nodes whose stored size the session changed are
dropped (host).

**6.3 Migration from 10.6 — migrate(prefs, H, L, chromeH) → view.** `prefs.nav_mode = "corner"` → `forceCollapse:
["navcol"]`. `prefs["call-pane-frac"]` a finite number ≥ 0 → `fm = round(f × 1000)` (the IEEE double product, then
round = floor(x) + 1 when x − floor(x) ≥ 0.5, else floor(x) — JavaScript `Math.round` for x ≥ 0), clamped to 200-850.
With fm: `H`, `L`, `chromeH` integers are clamped to [0, 16384] (not integers: H / L absent, chromeH 0); when H and L
are present and **L > 0** (the first normal solve with the call docked in a col: not maximised, not the
emergency arrangement; L = the inner length of the call's parent col, H = the host's outer height), the **seam
conversion** gives `sizes: {call: {pm}}`; otherwise `legacyCallPaneFm: fm` (the conversion waits). chromeH =
`content.call.collapsedH`.

**Seam conversion** (decision 9: the **nearest representable** height, Q-MIGRATE): `T = max(120 + chromeH, fdiv(fm ×
H, 1000))`; `p1 = fdiv(1000 × T, L)`; of `p1` and `p1 + 1`, each clamped to [200, 850], the one whose height `fdiv(pm
× L, 1000)` is nearest to T; a tie goes to the smaller pm. There is **no** fixed pixel bound: one per mille of L is
`L / 1000` px (8 px at L = 8000, e.g. fm 500, H 16016, L 16000: 500 and 501 both miss T = 8008 by 8 px → 500), and the
clamp to 200-850 can move the seam further; the result is the closest height the stored per mille can express.

**6.4 Reset** (host behaviour, decisions 4 and 10): every reset path sets a device-local override `{form: Classic,
baseTuple}` rendered at once, with Keep for all devices (a normal save) or Restore (drop the override); in edit mode
Reset is staged like any edit.

## 7. Solve

`solve(form, size, unitPm, shape, content, view) → output`. The form is a valid (repaired) desktop form or the
internal `classic-flush` preset. Pure, integer-only. Products of the clamped inputs stay below 2³¹; an **unbounded**
maximum is the constant 2⁴⁰ (and `LA + LB − max` in resize can reach −2⁴⁰), so Rust uses i64 for every intermediate
(i32 is not enough).

**7.1 Inputs, read leniently.** `size {w, h}`: integers clamped to [0, 16384], else 0. `unitPm`: integer clamped to
[500, 4000], else 1000 (web 1000; desktop `round(gridUnit × 1000 / 18)`). `shape` (`gap margin tab handle drawerW
drawerPad`, layout units): integers clamped to [0, 8192], else `x-tinhat.shapeDefaults`; the form's `gap` / `margin`
replace the shape's; then every key is raised to its **usable minimum** `x-tinhat.bounds.shapeMin` (`tab` 16, `handle`
24, `drawerW` 160; `gap`, `margin`, `drawerPad` 0), so no theme can make a tab strip, a handle or a drawer unusable
(Q-SHAPEMIN). `content` (the first 256 refs in code-point order; per ref `{w, h, minW, minH, collapsedH, barH}`
integers clamped to [0, 16384], else absent; `empty: true`). `view`: `roomOpen` a boolean, else **true**; `callShown`,
`panelOpen` true only when `true`; `maximized` a known ref whose registry is `maximizable` (the call), else null;
`forceCollapse` its string items, each once (first occurrence), at most 64; `sizes` per key an object read per §5.3;
`active` per key a string; `drawer.open` a string, else null; `popouts` its keys that are known refs whose registry
allows `popout` (Q-VIEWREAD, Q-CAPS); each map read over its first 256 keys in code-point order (§1.4).

**7.2 Arithmetic.** `fdiv(a, b)` = floor(a / b), b > 0 always (Rust `div_euclid`; never `/` or `%` on values that can
be negative). `sc(v) = sign(v) · fdiv(|v| · unitPm + 500, 1000)` (half away from zero; layout units → px).
`unscale(px) = fdiv(px · 1000 + fdiv(unitPm, 2), unitPm)` (px ≥ 0). Every layout length L is used as `sc(L)`.
**Host:** `g = sc(gap)`; `m = min(sc(margin), fdiv(W, 8), fdiv(H, 8))`; host rect `(m, m, max(0, W − 2m), max(0,
H − 2m))`.

**7.3 The solve tree and presence.** The root tree (and each float's node) is read as rows, cols, stacks and islands;
an **unknown node type** is a col whose size is `{share: 1}` and whose gap is the form gap, keyed `~<n>` where n is its
preorder index in the root tree (root = 0, every node counted) or `~f<i>.<n>` in float i (Q-UNKNOWNNODE). The **key** of
a node is its ref (islands) or id. An island is **present** iff it is a compat island, or it is known, not named in
`view.popouts` (as read, §7.1), not (no room open and header / composer / panel), and its registry presence holds:
`always`;
`room` = roomOpen; `call` = callShown; `open` = panelOpen; `content` = not `content[ref].empty`. Unknown islands are
never present. The call depends on `callShown` alone: an active call stays on screen with no room open (Q-CALLROOM). A container or stack is present iff one of its children is; absent nodes take no space and no gap
("pruning").

**7.4 Lengths along an axis** (a = w in a row, h in a col; L = the parent's inner length when known):
- **registry minimum** of an island = max(sc(registry `min[a]`, `orientH.min` when horizontal), `content.minW|minH`);
  compat islands: the content minimum; containers and stacks: 0.
- **min(n, a, L, along)** = the registry minimum, and when `along` (a is the parent's axis) also `sc(size.min)` and,
  with L known, `fdiv(minPm × L, 1000)`; for a row / col additionally the **recursive minimum**: along its own axis Σ of
  its children's `min(c, a, —, along)` + its gap × (n − 1); across it the largest `min(c, a, —, not along)`; for a stack
  the largest `min(c, a, —, not along)` + `sc(tab)` vertically. (Bottom-up: children's `minPm` is not counted here.)
- **max** = min(`sc(size.max)`, `fdiv(maxPm × L, 1000)` with L known), unbounded else; never below min.
- **floor**: a required island (timeline, composer, call): its registry minimum; a row / col: Σ of its children's
  floors along its axis (gaps not counted), the largest across; stacks and everything else 0.
- **natural**: an island — folded (by an applied `fold` step; the folds of the final collapse decision also apply
  inside overlays, collapse drawers and overflow drawers — only the drawers' side trial has none): its registry minimum
  (Q-FOLD); else `content.w|h` when present; compat: 0; else
  `sc(pref.fixed)` when its effective registry pref has one, else its registry minimum. A stack: the largest natural of
  all its present tabs, + `sc(tab)` vertically. A row / col along its axis: Σ of its children's bases with L unknown +
  gap × (n − 1); across: the largest child natural.
- **base**: `fixed` → sc(fixed); `auto` → natural; `pm` with L known → fdiv(pm × L, 1000); otherwise (share, pm
  without L) → min; then clamped to [min, max].
- **weight**: a share basis → its `share` (default 1); any other basis → its `grow` (default 0).

**7.5 Collapse.** Steps = the forced ones — each `view.forceCollapse` ref in order, `to` = the form's step for that ref,
else `drawer` for a container / stack and `hide` for an island; the form step's `below` / `w` carry over — then the form's
steps in order, skipping refs that were forced. **Trial** = distribute the pruned root tree, with the nodes removed by
the effects of the applied steps (`hide`, `overlay`, `drawer`; `fold` makes an island's natural its registry minimum),
in the host rect (§7.6). A step is **eligible** in a trial when its ref is a node of the working tree, it is safe (§3.5,
checked on the form's subtree, Q-SAFE) and a `fold` targets an island whose registry allows fold. Its **condition**:
forced → true; else P = the ref's parent in the working tree (the root's own parent: the root, rect = host); P not laid
out (squeezed out of its own container) → true (Q-SQPARENT); `below` set → P's length along P's axis (a row: width;
a col, stack or unknown node: height) < sc(below); `below` absent → P or any container under it is in the trial's
overflow list (Q-COND), or a required island under P (docked, z 0) is below its registry minimum on either axis.
- **Forward pass**, in order: trial with the steps applied so far; an eligible step whose condition holds is applied
  (a `fold` also folds its island). **Then until nothing changes** (Q-FIXPOINT): trial with the applied steps; the
  first step in order that is not applied, eligible and whose condition holds in that trial is applied. (Applying a
  step can shrink an earlier step's parent — a `share` container's length follows its content's minimum — so a step the
  forward pass skipped may hold afterwards; bounded by the number of steps.)
- **Release pass**, once, over the applied non-forced steps in reverse application order: trial with that step released
  (a fold unfolded) and every other decision kept; it is released only if the trial has no breach and no required
  island below its registry minimum, and no step that is not applied (released earlier, never applied, or this one)
  and is eligible in that trial has a true condition; otherwise the fold is restored.
- `collapsed` = `"<ref>:<to>"` of the applied steps in application order (the `to` is after the **last** colon).

**7.6 Docked distribution** of a row / col C in rect R along its axis (length `len`, cross length `clen`), children =
its present children in order (n):
1. **Gap**: g = C's own `gap` (sc) else the form gap; if n > 1 and g × (n − 1) > fdiv(len, 4) then g = fdiv(fdiv(len,
   4), n − 1). **L** = max(0, len − g × (n − 1)).
2. base, min, max, floor, weight per child (§7.4 with this L). R′ = L − Σ base.
3. **R′ > 0** and some weight > 0: repeat — R₀ = R′ at the start of the round; A = the weighted children not capped
   yet, S = Σ their weights (S = 0 → stop); each child of A (in order) gets `add = fdiv(R₀ × w, S)`; when `add ≥
   max − base` it gets `max − base` instead and is capped (leaves A); R′ = R₀ − Σ add; if nobody was capped this round,
   the remaining R′ units go one each, in order of (`R₀ × w mod S` descending, index ascending), to the children of A
   below their max (at most one each), and the loop ends; else the next round starts. With no weighted child the
   leftover stays empty at C's end.
4. **R′ < 0**: C **overflows**; need = −R′; passes from the last child to the first, each while need > 0: (1) children
   whose effective basis is `auto` or `pm` down to their min; (2) `fixed` children down to their min; (3) children
   with a floor down to their floor; (4) **squeeze-out**: a child with floor 0 and base > 0 gets length 0, need −= its
   base + (g when n > 1), and it is **squeezed**. need still > 0 → C is in **breach**.
5. **Squeezed children leave**: with `chip = min(sc(handle), len)`, C reserves `chip + g` at its end and distributes
   again over the remaining children in `max(0, len − chip − g)` with the first run's g (no gap squeeze), repeating
   while a run squeezes more (each run removes at least one child); overflow / breach accumulate. The chip rect is
   `(x + w − chip, y, chip, h)` for a row, `(x, y + h − chip, w, chip)` for a col. A squeezed subtree is never solved
   (its stacks and containers are not listed); its islands (in C's child order, each subtree depth-first) are listed in
   `squeezed` and appear as fresh leaves in the chip's overflow drawer (§7.9), whose rect is their final entry (the
   placeholder `(chip x, chip y, 0, 0, vis false)` exists only until the drawer is placed) (Q-SQUEEZE).
6. **Cross axis**: a laid-out child whose min across (not along) exceeds clen puts C in overflow; one whose floor across
   exceeds clen puts C in breach.
7. Children are laid out from C's start edge with g between them, each getting C's full cross length. C's key is
   recorded in `overflow` once (before its children are solved) when it overflowed.
8. **Gap handles** (docked distributions only, z 0, Q-GAPS): the gap between laid-out children i−1 and i is
   `{id: "<C key>/<i−1>", axis: x (row) | y (col), x, y, w, h, a: <key of i−1>, b: <key of i>}` with the rect
   `(pos − g, y, g, h)` for a row and `(x, pos − g, w, g)` for a col (pos = child i's start); it is emitted after child
   i−1's whole subtree and before child i's.
9. Every laid-out row / col — of the form, and unknown node types as cols under their `~` keys; not synthetic columns —
   is listed in `containers` with its rect and z, before its children.

**7.7 Stacks.** Tab strip `t = min(sc(tab), h)` at the top; every present child gets `(x, y + t, w, h − t)`; the
active tab: `view.active[id]` if it names a present child, else the stack's `active` if present, else the first present
child; only the active child's island is visible. Output `stacks[id] = {x, y, w, h, z, vis, tabs, active, tab}` (tabs =
the present children's refs; vis = w > 0 ∧ h > 0 ∧ its layer shown) — from every layer (Q-STACKOUT).

**7.8 Overlays.** For each applied `overlay` step in application order: P = the node's parent in the uncollapsed
pruned tree; P's axis: w when P is a row, else h (a col, a stack, an unknown node); P's rect = its final laid-out rect,
else the host rect; P's inner length = the L of P's first distribution run in the final trial, else (a stack, or P not
laid out) P's length (Q-OVERLAYL). The node (from the uncollapsed tree, pruned by the effects of the
**other** applied steps, Q-NESTED) gets along P's axis `min(base(node, a, inner), P's length)` and P's full cross
length; it sits at P's end edge when none of P's children after it (in the uncollapsed tree) remain in the final working
tree, else at the start edge; that rect is then **cut around the guard** (below) and the node is distributed in the
result at **z 2**.

**The guard** (Q-GUARD): the rects of the final trial's visible z-0 `composer` and `call` (in that order), then the
rect of a floating call (the first float holding the call, solved in its own float geometry, when the call is visible
there). An overlay's rect and every `reveal: always` float's rect (§7.10; a float holding the call skips the floating
call's own rect) are cut around each guard rect in order with the form gap g: `cut(r, q)` = r when r and q do not
intersect (strictly: `r.x < q.x + q.w ∧ q.x < r.x + r.w`, same for y); else the largest by area of r's parts above q
`(r.x, r.y, r.w, q.y − g − r.y)`, below `(r.x, q.y + q.h + g, r.w, r.y + r.h − q.y − q.h − g)`, left `(r.x, r.y, q.x −
g − r.x, r.h)` and right `(q.x + q.w + g, r.y, r.x + r.w − q.x − q.w − g, r.h)` that have positive width and height
(ties: that order), and `(r.x, r.y, 0, 0)` when none has. So nothing that stays on screen by itself ever covers the
composer or the call; transient layers (drawer panels, hover floats, overflow panels) open over them on demand and close
again (§11).

**7.9 Drawers.** `hx = min(max(m, 4), fdiv(W, 8), fdiv(H, 8))`; `hs = max(0, min(sc(handle), fdiv(W − 2hx − 4, 2),
H − 2hx))` — at most half of the width between the edge insets, so the first left and the first right handle never
overlap (Q-HANDLE). `pad = sc(drawerPad)` is the preferred padding used for panel sizes; `pd` is the final padding of a
placed panel.
- **Collapse drawers** (applied `drawer` steps, each node from the uncollapsed tree pruned by the other steps' effects):
  `side: "r"` iff `2x + w > 2·hostX + hostW` for the node's rect in the **uncollapsed trial** (no steps, no folds,
  Q-SIDETRIAL; the host rect when the node is not laid out there), else `"l"`. Per side in application order, k = index:
  handle `(hx + k(hs + 4), hx, hs, hs)` on the left, `(W − hx − hs − k(hs + 4), hx, hs, hs)` on the right. At most
  `kmax = max(1, fdiv(W − 2hx + 4, 2(hs + 4)))` per side: beyond that the drawers from index kmax − 1 on are **merged**
  into the last handle — one drawer with the first merged ref as id, `merged: [refs]`, whose node is a synthetic col
  keyed `~m.<first ref>` of their nodes; a merged drawer ignores the steps' `w`. Synthetic cols (`~m.…`, `emergency`,
  `overflow-…`) have size `{share: 1}` and the form gap.
- **Panel**: width `sc(step.w)` when set, else `min(sc(drawerW), natural width + 2·pad)` (`sc(drawerW)` when the natural
  width is 0), then at most `max(0, W − 2hx)`; `py = min(hx + hs + 4, max(0, H − hx))`; height
  `max(200, min(sc(680), fdiv(H × 820, 1000), H − 94))`, then `max(0, min(that, H − hx − py))`; x = hx (left) or
  `W − hx − pw` (right); padding `pd = min(sc(drawerPad), fdiv(pw, 4), fdiv(ph, 4))`; inner `iw = max(0, pw − 2pd)`,
  `ih = max(0, ph − 2pd)`. The node is distributed as a root in `(px + pd, py + pd, iw, ch)` with `ch = max(ih, its
  min height (not along))` at **z 20**; `scroll: ch` when ch > ih. Its islands are visible only while the drawer is open.
- **Insets**: after each collapse drawer, every z-0 island with a non-empty rect (visible or not — an inactive tab
  too) whose rect strictly intersects the handle gets `inset.l = handle.x + hs + 2 − island.x` (left) or `inset.r =
  island.x + island.w − handle.x + 2` (right), the largest over all handles.
- **Overflow drawers** (one per chip, from every layer — docked, overlays, floats, drawers — in that order, each in
  solve order, Q-CHIPS): node = a synthetic col `overflow-<C key>` of fresh leaves of the squeezed refs, laid out as a
  **plain list** (Q-OVERFLOWLIST): each leaf at its natural height (§7.4; no stored size, no `view.sizes`, no
  distribution — nothing inside an overflow panel can be squeezed again), the form gap g between them; `listH` = Σ
  naturals + g × (n − 1); `pw = min(sc(drawerW), the widest natural width + 2·pad, max(0, W − 2hx))`; `want = listH +
  2·pad`; room below
  `H − hx − (cy + ch + 4)`, above `cy − 4 − hx`, right `W − hx − (cx + cw + 4)`, left `cx − 4 − hx` (cx, cy, cw, ch =
the chip rect here); preference below,
  above, right, left for a row's chip (axis x), right, left, below, above for a col's; the first side whose room ≥ its
  need (below/above: `min(want, 200)`; right/left: pw), else the side with the most room (ties: earliest in the
  preference). Below/above: `ph = max(0, min(want, room))`, `py = cy + ch + 4` or `cy − 4 − ph`, `px = cx + cw − pw`;
  right/left: `pw = max(0, min(pw, room))`, `ph = max(0, min(want, H − 2hx))`, `px = cx + cw + 4` or `cx − 4 − pw`,
  `py = cy + ch − ph`; then `px` clamped to [hx, max(hx, W − hx − pw)], `py` to [hx, max(hx, H − hx − ph)], `pw =
  max(0, min(pw, W − hx − px))`, `ph = max(0, min(ph, H − hx − py))`; `pd = min(pad, fdiv(pw, 4), fdiv(ph, 4))`,
  `iw = max(0, pw − 2pd)`, `ih = max(0, ph − 2pd)`; the leaves at `(px + pd, y, iw, natural)` from `y = py + pd`, g
  between them; `scroll: listH` when listH > ih; drawer `{id: "overflow-<C key>", side: "chip", handle: the chip rect,
  panel, open, count: the number of squeezed
  refs, vis: the chip's layer shown, z: the chip's layer, scroll?}`; the panel's islands are visible when non-empty and
  `drawer.open` is this id (independent of the chip's layer); nothing else (stacks, containers, chips) is output from
  an overflow panel.

**7.10 Floats** (index i in `floats`, z = 10 + i; the node pruned for presence, skipped when absent). Width and height
from the float size (the key absent → the island node's registry `float` size, a group `{auto: true}`, Q-FLOATGROUP):
`fixed` → sc; `pm` → fdiv(pm × host length, 1000); `auto` / no basis → the node's natural size; clamped to
`[lo, max(lo, hi)]` with `lo = max(sc(min ?? 0), fdiv((minPm ?? 0) × host length, 1000))`, `hi = min(sc(max),
fdiv(maxPm × host length, 1000))` of the bounds present; a hover float then at least `min(hs, host length)` (Q-HOVER);
then clamped to [0, host length]. Position: anchors containing `l` → `x = hostX + sc(dx)`; containing `r` →
`hostX + hostW − w − sc(dx)`; `t` / `b` → `hostX + fdiv(hostW − w, 2) + sc(dx)`; y likewise from dy (anchors starting
with `t` / `b`; `l` / `r` centred); then x clamped to [hostX, hostX + hostW − w], y likewise; a `reveal: always` float
is then cut around the guard (§7.8). The node is distributed in that rect (overflow, squeeze-out, chips). `reveal: hover`: its islands visible only while `drawer.open` = the float's
id; drawer `{id, side: <anchor>, handle, panel: the float rect, open}` (a hover float's `side` is its anchor, so it
can be `l` / `r` like a collapse drawer's — its id is a float id) with the handle the hs square at `x = fx` (anchor
contains `l`), `fx + fw − hs` (contains `r`), else `fx + fdiv(fw − hs, 2)`; `y = fy` (anchor starts with `t`),
`fy + fh − hs` (starts with `b`), else `fy + fdiv(fh − hs, 2)`; then x clamped to [0, max(0, W − hs)], y to
[0, max(0, H − hs)].
**A floating call below its floor** (in its float's solve its rect is under its registry minimum on either axis, or
the float breached) sends the whole solve to the emergency arrangement.

**7.11 Order of a solve.** (1) `view.maximized` names a present island placed in the root or a float (Q-MAX) → it gets
the host rect (`vis` = host non-empty), nothing else is listed, done (only a `maximizable` island can be named, §7.1;
the host always offers the way back, §11). (2) The pruned root tree empty → floats and
their chips only (no floating-call check). (3) Collapse (§7.5). (4) The final trial; if it has a breach, a required island (z 0) below its
registry minimum, or a floating call below its floor → the emergency arrangement (§7.12). (5) Otherwise output the
final trial (islands, stacks, containers, gaps, overflow, squeezed), then overlays, floats, collapse drawers, overflow
drawers.

**7.12 The emergency arrangement E.** Ignores the collapse steps and the `sizes` overrides; folds cleared.
- **Column**: the present islands among header, call, timeline, composer — a floating call and a floating panel join
  (Q-EPANEL) — in the order header, call, timeline, composer (`opts.header.headerBottom === true` moves the header
  last; `opts.composer.composerTop === true` swaps timeline and composer). Full host width, x = hostX, the form gap g;
  `A(order) = hostH − g × (count − 1)`. `composer = max(its natural, its registry minimum)`; the call's **control bar**
  `callB = max(sc(registry call.bar = 48), content.call.barH ?? 0)` — a measurement can raise it, never erase it
  (Q-CALLBAR); `callC = max(content.call.collapsedH, else the call's registry minimum (Q-CALLC), callB)`; `callN =
  max(its natural, callC)`; `header` = its natural; `tlf` = the timeline's registry minimum. So `callN ≥ callC ≥ callB
  > 0` for an active call.
- **Levels**, the first that fits (levels 1-3 are tried only while the order holds a call, a composer or a timeline):
  1. everything (in levels 1-3 `composer`, `header` count 0 when not in the order, `tf` = tlf when the order holds a
     timeline, else 0): `call = clamp(A − composer − header − tf, callC, callN)` (0 without a call), `rest = A −
     composer − header − call`; fits when rest ≥ tf and — when the order holds a timeline — rest > 0; the timeline gets
     rest (with no timeline in the order the rest stays empty);
  2. the same without the header;
  3. without header and timeline: `call = clamp(A − composer, callC, callN)`; fits when `A − composer − call ≥ 0`
     (the rest stays empty);
  4. with a call and a composer, when `A ≥ callB + composer`: `call = min(callC, A − composer)` + the composer;
  5. with a call, when hostH ≥ callB: the call alone, `min(callN, hostH)`; without a call, with a composer, when
     hostH ≥ composer: the composer alone, hostH;
  6. **too small**: the call, else the composer, else the timeline gets hostH; `tooSmall: true` (Q-ENOROOM).
  The islands of the level are stacked from hostY with g between them; column islands not in the level get
  `(hostX, hostY, 0, 0, z 0, vis false)`.
- **Panel**: present → over the timeline's rect at its right edge, width `min(sc(324), hostW)`, z 2, when the timeline
  is visible; else `(hostX, hostY, 0, 0, z 2, vis false)`.
- **Drawer `emergency`**: every maximal subtree of the pruned root tree holding none of header, call, timeline,
  composer, panel (tree order, structure kept), then the islands of every float other than the call and the panel as
  fresh leaves; one node as is, several in a synthetic col keyed `emergency`; placed as a left collapse drawer at k = 0
  (§7.9, handle insets on the column) with its chips.
- Output: `emergency: true`, `collapsed: ["emergency"]`, no gaps, no overflow; `stacks`, `containers` and `squeezed`
  only from the emergency drawer (z 20).

**7.13 Output** (integers only; absent islands are not listed; objects keyed by ref / id):
`{islands: {ref: {x, y, w, h, z, vis, inset?: {l?, r?}}}, stacks: {id: {x, y, w, h, z, vis, tabs, active, tab}},
containers: {key: {x, y, w, h, z}}, drawers: [hover float `{id, side, handle, panel, open}` | collapse or emergency
drawer `{id, side, handle, panel, open, scroll?, merged?}` | overflow drawer `{id, side: "chip", handle, panel, open,
count, vis, z, scroll?}`],
gaps: [{id, axis, x, y, w, h, a, b}], collapsed: [], overflow: [], squeezed: [], emergency, tooSmall?}` — `vis =
w > 0 ∧ h > 0 ∧ shown` (inactive tabs, closed drawers and hover floats hide); `z`: 0 docked, 2 overlay, 10-17 floats, 20
drawer panels. **Array orders:** `drawers` = hover floats (float order), collapse drawers (left side then right side,
application order), overflow drawers (§7.9); `gaps` = layout order of the docked tree; `overflow` = the docked
containers that overflowed, pre-order; `squeezed` = docked, then overlays, floats, drawers. `tooSmall` only when true.

## 8. Operations

`applyOp(form, op, ctx?) → {ok: true, form, remap} | {ok: false, error}`; the input form is never modified. `form`
must be JSON data and an object, `op` JSON data, `ctx` absent or JSON data (§1.4) — else `bad-op: bad request`; the
form is the projection the host renders (§5), not repaired again here. `ctx` = `{size, unitPm, shape, content, view}`,
read like solve's inputs (§7.1): **`resize` and `resetSizes` need `ctx.size` with integer `w` and `h`** (else `bad-op:
bad request` — without a size there are no lengths to split); every other operation ignores `ctx`; `dropZones` reads a
missing `ctx` as a 0 × 0 window (no zones).

**8.1 The steps**, in this order (the first failure answers): (1) the op object's **shape**: not an object, an unknown
`op`, or a missing / ill-typed field → `bad-op: bad request` — `ref`, `target`, `a`, `b` strings; `side` one of left,
right, top, bottom; `anchor` one of the eight; `dx`, `dy` integers in ±4096; `reveal` absent, `always` or `hover`;
`delta` an integer in ±16384; `into` (resize) absent or a boolean (v1.2); `to` of `dock` a dockBeside / stackAsTab / edge placement with its fields, of `restore`
also a float placement; `setOpt`'s `ref` of ref syntax and `key` a non-empty string other than `composerTop` /
`headerBottom`; `applyPreset`'s `preset` a preset name. (2) **Resolve the moved node** by key in the root tree, then the
floats (known node types only): not found → `bad-op: island not placed`; an unknown island → `bad-op: unknown island`.
(3) **The target** (dockBeside, stackAsTab; also inside `dock` / `restore` placements): not found → `bad-op: target
not found`; the moved node itself → `bad-op: same island`; inside the moved group → `bad-op: target inside moved group`;
inside an unknown node or an unknown island → `bad-op: read-only layout`. (4) The moved node inside an unknown node, or a
group holding an unknown node or island → `bad-op: read-only layout`; the root → `bad-op: locked group`.
(5) **Capabilities**: float — the moved node's islands depth-first, each: known and not floatable → `bad-op: not
floatable`, then required with `reveal: hover` → `bad-op: required island`; stackAsTab — a group → `bad-op: not
stackable`, a known island that is not stackable → the same; hide — a group → `bad-op: not hideable`, required →
`bad-op: required island`, not hideable → `bad-op: not hideable`. (6) **Mutate a copy without normalizing** (N8 ids over
the form before the detach). (7) **Placement rules** on the mutated copy, in this order: (a) an island ref twice in the
root tree and the floats → `bad-op: locked group`; (b) each hidden entry in order: its ref seen before → `bad-op: locked
group`, required → `bad-op: required island`, not hideable → `bad-op: not hideable`; (c) every stack in order: a
non-island child or a known non-stackable island → `bad-op: not stackable`; (d) the floats in order, their islands
depth-first: known and not floatable → `bad-op: not floatable`, then required in a `hover` float → `bad-op: required
island`; (e) timeline, composer or call not placed in the root tree / floats, or hidden → `bad-op: required island`;
(f) R1 fails → `bad-op: locked group`; (g) the header in a float, or R2 fails → `bad-op: locked group`. (8) **Normalize**
once (§4), collecting the remap. (9) **Validate** (§5.4); the **first** violation decides: `replaced-by-classic <limit>`
→ `bad-layout: too large | too deep | too many nodes`, any other limit → `bad-layout: over a limit`;
`collapse-unsafe-dropped` → `bad-op: required island` (the move would make a collapse step hide the call or the room
group, Q-UNSAFEOP); `bad-opts-fixed` → `bad-op: bad request`; anything else → `bad-op: locked group`. (10) `{form,
remap}` (remap keys sorted).

**Dispatch** (Q-DISPATCH): which steps each operation runs and how it looks things up; step 1 (shape) and steps 7-10
run for every operation, "—" = the step does not apply.

| op | step 2: the moved node | step 3: target | step 4 | step 5 | step 6 |
| --- | --- | --- | --- | --- | --- |
| `dockBeside`, `stackAsTab`, `edge`, `float` | `ref` by key in the root tree, then the floats | `target` (dockBeside, stackAsTab) | read-only, root | stackAsTab, float | §8.2 insert / append a float |
| `dock` | `ref` = a float id (then its node; a node of unknown type → `read-only layout`) or the key of a node inside a float (a docked key or none → `island not placed`) | `to.target` | read-only, root | as `to.op` | as `to.op` |
| `hide` | `ref` as above | — | read-only, root; then a group → `not hideable` | required → `required island`, not hideable → `not hideable` | detach, hidden leaf with `from` |
| `restore` | `ref` in `hidden`: absent → `island not hidden` (first), unknown → `unknown island` | `to.target` when `to` has one | the target's read-only check | as `to.op` | `to`, else `from`, else home rules (§8.2) |
| `resize`, `resetSizes` | `a`, `b`: consecutive laid-out children of one docked container of the ctx solve, known nodes of the form (else `target not found`) | — | read-only: either inside an unknown node or holding an unknown node / unknown or compat island | — | write the sizes (`no room`, §8.2) |
| `setOpt` | — (`ref` of ref syntax; the island need not be placed) | — | — | — | set / remove the key |
| `applyPreset`, `reset` | — | — | — | — | the preset's desktop form |

**8.2 Moving** (sizes, Q-OPSIZE): an island inserted by `dockBeside` or `edge` gets its registry pref for the new
parent's axis (`sizeForAxis`: the orientation-aware pref of §3.3), except a reorder inside the same container, which
keeps its size; a moved group keeps its size when its new parent has the same axis as its old parent and gets
`{share: 1}` otherwise (a group that was a float's node has no old axis: `{share: 1}`); whenever a size is replaced this
way, the unknown keys of the old size ride along. `stackAsTab` and `float` keep the node's size.
- **dockBeside(ref, target, side)** (`side` left | right | top | bottom): target in a stack → the stack; P = the
  target's parent; P a row / col with the side's axis (left/right → row) → insert before (left/top) or after; else the
  target is replaced by `{t: <axis>, id: n<k>, size: <the target's size object as it is, if any — unknown keys
  included>, c: [ref, target]}` (or `[target, ref]`) and the target gets a plain `{share: 1}` — also when the target
  is a float's node or the root.
- **stackAsTab(ref, target)**: ref an island; target a stack → appended, `active = ref`; target an island in a stack →
  inserted after it, `active = ref`; target a stackable island elsewhere → replaced by `{t: "stack", id: s<k>, size:
  <copy of the target's size>, active: ref, c: [target, ref]}`; anything else → `bad-op: not stackable`.
- **edge(ref, side)**: the root has the side's axis → ref becomes its first (left/top) or last child; else root :=
  `{t: <axis>, id: n<k>, c: [ref, oldRoot]}` (or `[oldRoot, ref]`) with the old root's size `{share: 1}`.
- **float(ref, anchor, dx, dy, reveal?)**: dx, dy integers in ±4096, reveal `always` (default) or `hover`; appends
  `{id: f<k>, anchor, dx, dy, w: <registry float.w>, h: <registry float.h>, reveal, node: ref}` (w / h only for an
  island with a registry float size).
- **dock(ref, to)**: ref = a float id (its node moves; a node of an unknown type → `bad-op: read-only layout`) or the
  key of any known node inside a float; a docked node or a key not found → `bad-op: island not placed`; `to` =
  `{op: dockBeside, target, side}`, `{op: stackAsTab, target}` or `{op: edge, side}`, run with that node. (Every moving
  operation also accepts a floated node directly.)
- **hide(ref)**: detached and appended to `hidden` as the whole leaf with `from: {parent: <its container / stack id, or
  its float's id when it was the float's node>, index}`.
- **restore(ref, to?)**: ref not in `hidden` → `bad-op: island not hidden` (checked first); an unknown ref →
  `bad-op: unknown island`; it leaves `hidden` (its `from` read and removed) and keeps its size in every path
  (Q-RESTORESIZE). With `to` (a placement `{op: dockBeside | stackAsTab | edge | float, …}`): its target is checked as
  in (3), its capabilities as in (5), then as that operation. Else at `from` when that node exists outside unknown nodes
  and accepts it — a row / col, a stack (the island stackable) or a float whose node is a row / col — inserted at
  `min(index, children)`, if the placement rules hold (then steps 8-10 decide, and their error is the answer — no
  fallback); else by the home rules (§3.8, full placement check).
- **resize(a, b, delta)** (delta an integer in ±16384): a and b must be consecutive laid-out children (a first) of one
  docked container C in the ctx solve and known nodes of the form (else `bad-op: target not found`), neither inside an
  unknown node nor holding an unknown node or an unknown / compat island (else `bad-op: read-only layout`); from C's
  final distribution (the ctx solve, `view.sizes` included): lengths LA, LB,
  minA/maxA, minB/maxB (px), C's inner length Lc. `t = 4 × fdiv(LA + delta + 2, 4)`; `lo = max(minA, LA + LB − maxB)`,
  `hi = min(maxA, LA + LB − minB)`; lo > hi → `bad-op: no room`; `L′A = clamp(t, lo, hi)`, `L′B = LA + LB − L′A`.
  Write-back on the **stored** effective sizes (§3.3, materialized; `view.sizes` ignored): exactly one of a / b has a
  `share` basis → it stays and absorbs, the other gets its new length; both share → a becomes `pm`; neither → both
  written. A written length:
  `pm` basis (or a becoming pm) → `pm = fdiv(L′ × 1000 + fdiv(Lc, 2), Lc)` (Lc = 0 → `bad-op: no room`), clamped 0-1000;
  otherwise (`fixed`, `auto`) → `fixed = unscale(L′)` clamped 0-8192; the other size keys stay (grow included).
  **v1.2 `into: true` (Q-RESIZEINTO):** before the clamp, each side is resolved to the node that takes its change: side a
  = a itself, then — while that node is a row / col with C's axis, its effective basis is `auto`, it has a distribution
  record in the ctx solve with at least one laid-out child, and that child (a's **last** laid-out child; for side b its
  **first**) is a known node outside unknown nodes whose effective basis is not `share` — that child (its length, min,
  max from its container's distribution; Lc = that container's inner length). A side resolved to a descendant a′ narrows
  the bounds: `lo = max(lo, LA − (La′ − mina′))`, `hi = min(hi, LA + (maxa′ − La′))`; for b′: `lo = max(lo, LA + Lb′ −
  maxb′)`, `hi = min(hi, LA + Lb′ − minb′)`. The write-back then runs on the resolved nodes with their own lengths moved
  by the same amount: `L′a′ = La′ + (L′A − LA)`, `L′b′ = Lb′ − (L′A − LA)` (share / pm / fixed rules as above, each with
  its own Lc); the containers between keep their `auto` size. `into` absent or `false` = exactly v1.1.
- **resetSizes(a, b)** (consecutive children as for resize): an island gets its registry pref for C's axis, a group
  `{share: 1}` (unknown size keys kept).
- **setOpt(ref, key, value?)**: ref of ref syntax, key a non-empty string other than `composerTop` / `headerBottom`
  (derived, N9); `opts` is created when absent and a non-object `opts[ref]` replaced by `{}`; with `value` →
  `opts[ref][key] = value`, without → the key removed (and the entry when that emptied it, `opts` itself stays); invalid
  known values are refused by step 9.
- **applyPreset(preset)** / **reset**: the named preset's desktop form (`bad-op: bad request` for other names).
- Presets and resets in an edit session change only the working copy; Done saves (§9), Cancel discards; the undo
  stack holds whole forms (host).

**8.3 dropZones(form, ctx, dragged) → {hit, keys}** (step 4): dragged = the key of a placed island / group (a float
id cannot be dragged), or a hidden island (then every zone's op is wrapped as `{op: restore, ref, to: <the op without
ref>}`); anything else → empty lists. From the ctx solve (host rect `(hx, hy, hw, hh)`, window W × H, `cw = min(48, hw)`,
`ch = min(48, hh)`, `bw = min(24, W)`, `bh = min(24, H)`): four **corners** `tl (hx, hy)`, `tr (hx + hw − cw, hy)`,
`bl (hx, hy + hh − ch)`, `br (hx + hw − cw, hy + hh − ch)`, each `cw × ch` → `{op: float, ref, anchor, dx: 8, dy: 8}`;
four **window-edge bands** `left (0, 0, bw, H)`, `right (W − bw, 0, bw, H)`, `top (0, 0, W, bh)`, `bottom (0, H − bh,
W, bh)` → `{op: edge, ref, side}`; then for every output island T that is visible, z 0, an island node of the form and
not the dragged node or inside it, in code-point order of refs, with `d = min(48, fdiv(T.w, 4))`, `dv = min(48,
fdiv(T.h, 4))`: four **edge bands** `left (T.x, T.y, d, T.h)`, `right (T.x + T.w − d, T.y, d, T.h)`, `top (T.x, T.y,
T.w, dv)`, `bottom (T.x, T.y + T.h − dv, T.w, dv)` → `{op: dockBeside, ref, target: T, side}`, and the **centre**
`(T.x + d, T.y + dv, T.w − 2d, T.h − 2dv)` → `{op: stackAsTab, ref, target: T}`. A zone is listed only when its rect is
non-empty and its operation succeeds on the form (Q-DROPZONES). Zone `{kind: corner | window | edge | centre, rect, op}`.
Tie keys: target = T's ref (`""` for corners and window bands); side rank left 0, right 1, top 2, bottom 3, tl 0, tr 1,
bl 2, br 3 (a centre ranks 0). **hit** order (the pointer's zone is the first containing it): kind (corner, window,
edge, centre), area ascending, y, x, target (code point), side rank. **keys** order (arrow keys): y, x, kind, area,
target, side rank.

## 9. Document, save, merge, sync

**9.1 The document** (global account data `dev.tinhat.layouts`): `{format: "tinhat-layouts", v: 1, layouts: [...],
conflicts?: [...]}` + unknown top-level keys. `layouts` holds the **current entry** (the winner, §9.3) of every layout
id, sorted by id; `conflicts` — present only when not empty — the **concurrent losers** that no current entry
incorporates, sorted by id, then merge order (highest first): the durable record that a save lost a race (Q-CONFLICTS).

An **entry**: `id` (id syntax), `rev` (0..2³¹−1), `savedAt` (ms, 0..2⁵³−1), `by` (the saving device's id: 1-64 code
points, no `#`; `""` = unknown, an older draft), `vv` (its version vector, below), and either **live** — `name` (1-40
code points), `desktop`, `phone`, optional `previous` (the entry it replaced, minus that entry's own `previous` and
`quarantine`), optional `quarantine` (`{desktop?, phone?}`: originals this version could not read, §9.5) — or a
**tombstone** (`deleted: true`; no name, forms, previous or quarantine). Unknown entry keys are kept.

**Version vectors.** `vv` maps a **chain key** to a counter (an integer 1..2³¹−1). A chain key is a device id, or a
device id + `#` + a canonical integer of 1-10 digits (`d2`, `d2#17`); every save counts under exactly one chain key of
its device, with the device's save counter (§9.7). An entry's **own key** (its save's "dot") = among the keys of its vv
whose device part is its `by`, the one with the largest counter (ties: the smaller key); an older draft may have none.
**B includes A** (A's save is in B's history) iff `B.vv[own(A)] ≥ A.vv[own(A)]` (a missing key reads 0); for an A
without an own key, iff `B.vv[k] ≥ A.vv[k]` for every k of A's vv (so an entry with no counters is included by every
entry). **B strictly includes A**: B includes A and A does not include B. A vv holds at most **16 counters**: a longer
one keeps first the keys its rule names — a save: its own key, then the own keys of `also` and of `start`; a read: the
entry's own key — then the other keys by larger counter (ties: the smaller key); the kept keys are sorted. A dropped
counter only makes an entry claim less history: a long-superseded version still held by a stale device may come back
as a conflict (Dismiss clears it), nothing is ever lost (Q-VVCAP).

**Tuple** = (rev, savedAt, by), compared lexicographically (by in code-point order); an invalid field reads as 0 / 0 /
`""` (older drafts). The **merge order** compares tuples, then the canonical texts (code-point order) — a total order.

**Defaults filled** (every entry this version reads from a document or from `known`; a copy): rev / savedAt / by set to
their tuple values; `vv` = its valid counters (valid keys, integers 1..2³¹−1; not an object → `{}`), capped, keys
sorted; a tombstone loses `name`, `desktop`, `phone`, `previous`, `quarantine` (unknown keys stay); a live entry loses
a `deleted` that is not `true`, gets its id as name when it has no valid one, the built-in Classic for a form that is
not an object, loses a `previous` that is not an object with desktop and phone objects (a snapshot's own `previous` and
`quarantine` are dropped) and a `quarantine` that is not an object (Q-DEFAULTS).

**9.2 Reading.** `readDoc(value)`: not JSON data, not an object, `format` ≠ `tinhat-layouts`, `v` not a number, or over
the **input budget** (canonical size > 1 MiB, or more than 1024 items in `layouts` + `conflicts`) → **ignore** (the
device keeps what it knows; nothing is latched, Q-BUDGET); `v > 1` → **newer**: rendered best-effort, **no writes of
any kind** (§9.7); `v = 1` → ok; anything else → ignore. A document's entries per id: the valid-id objects of `layouts`
and `conflicts`, defaults filled, reduced (§9.3).

**9.3 The reduction** `reduce(entries of one id) → [w, …conflicts]`: per version vector (equal canonical vv) only the
highest in merge order; **w** (the winner, the current entry) = the highest of all in merge order; the **conflicts** =
every other remaining entry that w does not include and that no other remaining entry strictly includes, in merge order
(highest first), each without `previous`. While every vv records its whole history (no counter dropped by the cap),
reduce is a **join** — commutative, associative, idempotent: `reduce(reduce(A) ∪ B) = reduce(A ∪ B)` — so every order
of merges and deliveries gives the same result (Q-JOIN). **Nothing is silently lost:** an entry leaves the reduction
only when another kept entry includes it — its save is in that entry's history (the chain rule, §9.7, makes inclusion
follow real history; the cap can only weaken it).

**9.4 Projection** — `project(value, activeId) → {read, layouts, active, name, desktop, phone, notes: {desktop, phone},
conflicts, quarantine}`: `read` = readDoc's kind (a newer document is projected too); the live ids (their w is live) in
code-point order; the active layout = `activeId` if live, else `main` if live, else the first live one, else built-in
Classic (id `main`, name `Main`); its w's desktop and phone forms repaired (§5) with their notes; `conflicts` = the
active layout's conflicts as `{rev, savedAt, by, deleted}` in merge order; `quarantine` = its w has one. The host shows
both (§11).

**9.5 save(raw, known, {id, edit, start, also?, now, by, seq, key?}) → {entry, doc} | {noop} | {error}** — a **new**
entry that always wins its own merge:
- raw newer → `bad-save: newer format` (raw ignored → as absent). Then `bad-op: bad request` unless: `id` of id syntax,
  `edit` an object, `now` an integer 0..2⁵³−1, `by` a device id (1-64 code points, no `#`), `seq` an integer ≥ 1,
  `key` (default `by`) = `by` or `by#<n>` (n canonical, ≤ 2³¹−1), and — for a live edit (`edit.deleted` not `true`)
  — `desktop` and `phone` objects. Then `seq` > 2³¹−1 → **`bad-save: exhausted`**.
- state = reduce(raw's entries of id ∪ `known`'s entries of id); base = its w. Base's rev = 2³¹−1 → `bad-save:
  exhausted` (Q-SAVEWIN: a revision never wraps or saturates; a save that could not win is refused, never reported as
  a success).
- **delete** (`edit = {deleted: true}`): no `also` and base absent or a tombstone → noop.
- **live** (`edit = {name?, desktop, phone, discardQuarantine?}`): name = the edit's valid name, else base's (live),
  else the id. No `also`, no `discardQuarantine: true`, and `start` live with the same name and canonically equal forms
  → **noop** (a session that changed nothing saves nothing). Base absent or a tombstone and at least 12 live layouts
  with another id in merge(raw, known) → `bad-save: too many layouts`.
- `vv` = the component-wise max of `start`'s and `also`'s (the entry the session started from — not the one current at
  Done — and, for Restore / Dismiss, the conflict); `vv[key] = seq`; capped (§9.1).
- entry = base's unknown entry keys (live saves only) + `id`, `rev` = base's rev + 1 (1 without base), `savedAt = now`,
  `by`, `vv`, and `deleted: true` (delete) or `name`, `desktop`, `phone` (copies), `previous` (base live and its forms
  canonically different → base minus its `previous` and `quarantine`; base live, forms equal → base's `previous` (if
  any); else none) and `quarantine`:
- **Quarantine** (Q-QUARANTINE): base live and no `discardQuarantine: true` → q = a copy of base's `quarantine` (else
  `{}`); for `desktop`, then `phone`: q lacks the key and repairing base's form answers `replaced-by-classic …` (§5.1,
  §5.6: the whole form was unreadable here and the user saw Classic) → `q[key]` = base's form, verbatim; q not empty →
  the entry's `quarantine`. With `discardQuarantine: true` the entry has none. A form this version could not read is
  never overwritten silently: it rides along with every later save until the user discards it or a version that reads
  it restores it.
- doc = merge(raw, known with its entries of id replaced by reduce(state ∪ {entry}), justSaved = id); tooLarge →
  `bad-layout: too large` (the edit stays open). The entry's rev exceeds every rev of the state, so it is the new w.

**9.6 merge(raw, known, justSaved?) → {doc, tooLarge}**: `raw` is used as it is — its `layouts` and `conflicts` read as
in §9.2 without the budget or the version check (the caller decides), its unknown top-level keys kept; `known` maps
anything to an entry or a list of entries, each taken under its own valid id (the map's keys are not used); per id
`reduce(raw's ∪ known's)`; `layouts` = the winners sorted by id; `conflicts` (only when not empty) = the other entries,
sorted by id, then merge order (highest first); `format`, `v: 1`. Nothing is ever dropped — no entry, tombstone,
conflict or quarantine (Q-NOTRUNC) — except by the **size rule**: while the canonical size exceeds 65,536 bytes, drop
`previous` from the live winner with the oldest savedAt (ties: the smaller id) other than `justSaved`, then from
`justSaved`; still too large → `tooLarge: true` (a save is refused and the user is told; a re-assert puts the document
anyway, so nothing a device holds is dropped).

**9.7 The device protocol** (a deterministic state machine; the `sync` vectors replay it). State: `counter` (the
device's successful saves), `chains` (per layout id `{key, last}`), `known` (per id the reduced list), `own` (per id its
latest save until settled), `lost` (per id its latest save that lost a race — a local hint; the durable record is the
document's `conflicts`), `raw` (the last accepted document), `maxV` (the highest `v` ever seen: the **newer-format
latch**), open sessions (per id the start entry), `wantPut`, the last saved id.
- **The chain rule** (Q-CHAINS): save `seq` of layout id counts under the device id for the device's first save of that
  layout; under `chains[id].key` when the save builds on the device's last save of the layout (`start` or `also` has
  `vv[chains[id].key] ≥ chains[id].last`); else under a **new chain** `<device>#<seq>`. So a device's later save never
  claims an earlier own save it does not incorporate (that save stays a conflict until resolved), and within a chain
  every save includes the one before — which is what makes "includes" (§9.1) follow real history.
- **Durability** (host): `counter`, `chains`, `known`, `own`, `lost` and `maxV` are persisted before a put that carries
  a save; a device that loses them takes a **new device id** (an old id with a lower counter would make new saves look
  old).
- **read-only** = `maxV > 1`. A `v: 1` event never clears the latch (a delayed or reordered one cannot re-open writes);
  only the host clears it — after an update that reads the newer format, or when the user explicitly confirms that the
  newer app is gone (§11).
- **begin(id)**: a session already open → `open`; else start = the current w of id (the reduction of raw's entries —
  none while read-only — and `known[id]`) → `begun`.
- **save / delete (Done)**: `read-only` while read-only; start = the open session's (else the current w), the session
  closes; `seq = counter + 1`, the key by the chain rule; a success: `known[id]` := reduce(state ∪ {entry}), `own[id]` :=
  entry, `counter = seq`, `chains[id] = {key, last: seq}`, a put is wanted, the last saved id = id (`saved`); a noop
  changes nothing (`noop`); an error (re)opens the session with that start (the error code).
- **restore / dismiss (id, pick = 0)**: `read-only` while read-only; an open session of id, or no conflict number
  `pick` (0 = the first after w in the current reduced list) → `none`; else a save with start = w, `also` = that
  conflict and as edit: **restore** — the conflict's name (when a string) and forms (a tombstone conflict: a delete);
  **dismiss** — w's name and forms (w a tombstone: a delete); on success `lost[id]` is cleared when the new entry
  includes it. The new entry includes both w and the conflict, so both leave the reduction.
- **put**: when wanted and not read-only, the server document := merge(raw, known, the last saved id since the previous
  put), then nothing is wanted and the last saved id is forgotten (`put`); else `idle`.
- **receive(D)** (every account-data event, the echo of its own put included): ignore per §9.2 → `ignored`; else `maxV
  := max(maxV, D.v)`, raw = D; read-only → `read-only`; else for every id of D: `known[id]` := reduce(`known[id]` ∪ D's
  entries of id); for every id of `own` (code-point order), M = `own[id]`, w = the current w: w has M's tuple and M's
  vv → still current, kept; else M is **lost** when w does not include M (`lost[id]` := M, reported), settled otherwise,
  and `own[id]` is cleared; then every `lost[id]` that the current w includes is cleared (resolved here or elsewhere);
  finally, when merge(D, known) differs canonically from D, a put is wanted (**re-assert**; the host delays it by a hash
  of the device id → 0-2 s; retries back off 1, 2, 4 … s up to 5 min and never give up while online). Result: `lost
  <id>[,<id>…]` for the reports, else `ok`.
- **Guarantees** (the sync simulator checks them over the real engine on random interleavings, §10.4): **C1**
  convergence — once the network drains, every device knows exactly the server's entries and nothing more is put;
  **C2** the highest save ever made of an id is the server's w; **C3** a device's superseded save is reported lost iff
  the winner's history lacks it (below the vv cap); **C4** nothing silently lost — every save ever made is in the
  history of its layout's final w or of one of its final conflicts (a dismissed conflict is in w's history). Also kept
  verbatim: other entries and unknown top-level keys (except the size rule's `previous` drops and the defaults
  filled), the saved entry's unknown keys from its base, inside the saved forms whatever the edit session's form (a
  projection, §5) kept — unknown keys of surviving nodes (incl. inside sizes), unknown node types, unknown islands,
  hidden leaves — and the quarantine. A change an older app could damage bumps `v`.

## 10. Test vectors and the independent checker

**10.1 Files**: `testvectors/layout/<kind>/<name>.json`, one vector per file, canonical pretty JSON, every vector has
its `kind`, `expect` computed by the TypeScript reference (`tools/layout/vector-run.mjs`). A vector's form is `form`, or `preset` = a preset name
of `x-tinhat.presets` or `internalPresets` (its desktop form).
- **solve** `{form|preset, size, unitPm, shape?, content, view, expect}` — expect = the §7.13 output.
- **op** `{form|preset, op, ctx?, expect: {form, remap} | {error}}`; an error means the input form came back unchanged.
- **dropzones** `{form|preset, dragged, ctx, expect: {hit, keys}}`.
- **repair** `{target: desktop|phone|document, text, active?, expect}` — desktop / phone: `{form, notes}` of the text
  read per §1.1; document: the projection `{read, layouts, active, name, desktop, phone, notes: {desktop, phone}}`.
- **validate** `{target: desktop|phone, form, expect: {violations}}`.
- **save** `{raw?, known, save: {id, edit, start?, also?, now, by, seq}, expect: {entry, doc} | {noop: true} |
  {error}}`; **merge** `{raw?, known, justSaved?, expect: {doc, tooLarge}}`.
- **sync** `{devices, server?, steps, expect: {log, server, devices: {<name>: {counter, known, own, lost, readOnly,
  wantPut}}}}` — steps `{device, event, …}`: `begin {id}`, `save {id, edit, now}`, `delete {id, now}`, `restore {id,
  now}`, `put`, `deliver` (receive the server document), `incoming {doc}` (receive a scripted document), and
  `{event: serverPut, doc}` (another writer); log lines `"<step> <device|-> <event>: <result>"` (step = 0-based index)
  with the results of §9.6, `set` for serverPut and `bad-step` for an unknown event; `known` optional in save / merge
  vectors (empty).
- **migrate** `{prefs?, H?, L?, chromeH?, expect: {view}}`.

**10.2 What they cover**: every repair note and every error code the engine returns (appendix A), R1-R3, N1-N9 incl. the unknown-keys exceptions and the
remap, every overflow pass incl. squeeze-out of a lone child and of every child, breach, gap squeeze, the release pass
(Astra's counterexample), drawers on both sides, merged drawers, scrolling drawers, float clamps and negative offsets,
hover floats smaller than their handle, stack fallbacks, every emergency level incl. too small and no room open, a
floating call and a floating panel in E, rounding at unitPm 500/889/1111/4000, the ISLANDS-ARCH §3.2 worked examples and
the prototype's examples, the preset grid (every preset × sampled sizes 480-3840 × 120-2160 × views × two content
sets), seeded random forms (xorshift32, the seed in the name) and seeded operation sequences from every preset, the JSON
reader's rules as text, the document projection, the save / merge preservation cases, the merge laws on generated
pairs, scripted sync scenarios (an acknowledged save overwritten by a stale put, cross-layout overwrites, a same-layout
race with Restore, identical-form saves, several intervening saves, a session that saw a remote save, delete vs edit,
delayed / reordered events, newer format, garbage) and seeded random sync runs, and the seam conversion.

**10.3 Independent checks** (`tools/layout/invariants.mjs`, byte-identical everywhere; written without the solver's
code: it reads the form, the registry, the inputs and the output and re-implements only `sc()`): for every solve vector
and every random case — **I1** integers, non-negative sizes (islands, stacks, containers, drawer handles and panels,
gaps); **I2** containment: z 0 / 2 / 10-19 islands inside the host, z 20 islands inside a drawer panel incl. its scroll
length; **I3** no two visible docked islands overlap; **I4** required floors outside E (docked and floating); in E the
call's height ≥ its bar and the composer's ≥ its floor whenever the host has room (heights, not visibility: a host that
reports `barH: 0` gets a 0-px call); **I5** every present
placed island is listed (islands under an applied `hide` step excepted) and nothing else; **I6** determinism (two runs,
same bytes); **I8** visible ⇒ non-empty; **I9** drawer chrome inside the window (a chip inside its layer: the host, or a
drawer panel); **I10** maximised = exactly the host rect; **I11** nothing at z 2-19 covers the emergency column, which is
full width, no gaps; **I12** at most one drawer open; **I13** every squeezed island sits in an overflow drawer's panel;
**I14** collapse-drawer handles never overlap (hover floats excluded: their `side` is the anchor); **I15** a docked chip never covers a visible docked island; **I16** no form
step that is not applied has a true `below` condition in the final geometry (parent rects from `containers`); **I17**
a stack's active tab is one of its tabs and its strip fits. For operations: the island multiset (root, floats,
hidden) is preserved by every successful non-preset operation; every result validates; an error leaves the input
unchanged (compared before / after); a replay of a seeded sequence gives the same bytes. For repair: the projection
validates, repair is idempotent, a valid form repairs to itself.

**10.4 The port.** C1-Rust reproduces every vector (`expect` byte for byte in canonical form), runs ≥ 10⁵ seeded
differential cases against the TypeScript reference, and pipes its outputs through `invariants.mjs` (node is on the

N SEED` (the property run); `tools/layout/proto-diff.mjs N SEED` (differential against the P5 prototype with the C0
resolutions, `tools/layout/proto/solve_proto_c0.py`); `tools/layout/sync-sim.mjs RUNS SEED` (the sync protocol over the
